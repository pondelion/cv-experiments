# mot: 画像のモデル + 独立した追跡の手法による複数物体の追跡

動画の各フレームで物体を見つけ(画像のインスタンスセグメンテーション・物体検出のモデル)、見つけた物体をフレーム間でつないで
動画を通した ID を付ける(独立した追跡の手法 = MOT の手法)、**2 段の構成(tracking-by-detection)**を検証する。

最終的な目標は 2 つ。

1. 2 段の構成で、最新の論文と同じかそれ以上の追跡の精度・速度にする(追跡の手法はスクラッチで実装する)
2. 動画のモデル(物体の検出と追跡を 1 つのモデルで学習する方式。[segmentation/instance_segmentation の 005xx](../segmentation/instance_segmentation/exp00502_video_arch_comparison/))と
   同じデータ・同じ評価で並べ、どちらがどの条件で強いか(精度・速さ・学習の手間)を明らかにする

## 対象にする方式

- **扱う**: 画像のモデル(1 フレームずつ物体を見つける)+ 独立した追跡の手法(フレーム間の物体の対応付けと、動画全体での ID の管理)。
  画像のモデルは、これまでのインスタンスセグメンテーションの実験([segmentation/instance_segmentation/](../segmentation/instance_segmentation/))
  の自作のモデルを主に使う。マスクから枠も作れるので、枠の追跡(MOT)とマスクの追跡(MOTS)の両方を測れる。物体検出のモデル
  ([object_detection/](../object_detection/))ができたら、それも画像のモデルとして入れる
- **扱わない**: 検出と追跡を 1 つのモデルの中に持ち、動画のデータで一緒に学習する方式(VidEoMT・DVIS・MOTR など)。これは
  [segmentation/instance_segmentation/exp00502](../segmentation/instance_segmentation/exp00502_video_arch_comparison/) で扱う
- 境目の方式の扱い:
  - 学習する追跡の手法(CAMELTrack・TDLP など)は、**画像のモデルを固定し、その出力(枠・マスク・特徴)だけを入力にして追跡の部だけを
    学習する**ものなら扱う。追跡の部を DETR 系の検出の部に足して一緒に学習する方式(MOTIP)も、検出の部を自作の画像のモデル
    (GTR 系など、クエリの特徴を出すもの)に置き換えられるので扱う(exp00202。まず画像のモデルを固定して追跡の部だけを学習し、次に
    公式どおり一緒に学習する)
  - マスクの伝搬を追跡に使う方式(SAM 2 の伝搬を使う SAM2MOT・McByte など)は、伝搬のモデルを学習し直さずに使う形なら扱う。
    伝搬のモデルを学習する SAM 3 型・DEVA は exp00502 で扱っている(結果はそちらを参照して並べる)

**MOT の仕組み(動画全体での物体の ID の管理)の書き方**: 実装するどの追跡の手法も、次の 4 つを README とコードの先頭に必ず書く。

| 項目 | 中身 |
|---|---|
| 対応付け | 今のフレームの検出と、追っている物体(track)を何で比べるか(枠の IoU・マスクの IoU・動きの予測・見た目の特徴(ReID)など)と、どう決めるか(ハンガリアン法・段階を分けた照合など) |
| 見失った物体の保持(再出現) | 照合できなかった物体を何フレーム残すか、残している間の位置・特徴をどう持つか、再び出たときに何で同じ ID に戻すか |
| 新しい物体(track の開始) | どの検出から新しい ID を始めるか(確信度(検出ごとの confidence score)の閾値・何フレーム続いたら確定するか) |
| 消えた物体(track の終了) | いつ ID を終えるか |

## 方針

- **追跡の手法**: スクラッチで実装する。公式のコードは、規則と設定の値を読み取る参考と、同じ検出を入れて値がそろうかの確かめに使う
  (コードは写さない。AGPL のコード(BoxMOT など)は読まない)。ハンガリアン法・カルマンフィルタの行列の計算などはライブラリ
  (scipy・lap)を使う
- **画像のモデル**: 追跡の手法の比較では固定する(同じ検出に全部の追跡の手法をかける)。画像のモデルの違いが追跡に与える影響は、
  別の比較として、追跡の手法を固定して測る
- **評価**: 公式の TrackEval のコードで HOTA・DetA・AssA・IDF1・MOTA を計算する(マスクのデータは、マスクの IoU で同じ指標)。
  公開の追跡の手法の値を、公式の検出で再現できることを最初に確かめる
- **設定の値の選び方**: 追跡の手法の閾値などは、各データセットの val の役のセットだけで選び、test の役のセットでは選ばない
  (データセットごとの役は exp00001 で決める)
- **速さ**: 画像のモデルと追跡の手法を分けて、フレームあたりの時間を測る。CPU(エッジの機器)・ブラウザで動かすことを考え、
  ONNX Runtime の CPU(1・4 スレッド)でも測る

## 比較の軸

| 軸 | 中身の例 | 学習し直し |
|---|---|---|
| 対応付けの手がかり | 枠の IoU / マスクの IoU / 動きの予測(カルマンフィルタ・観測を中心にした補正・非線形の動き)/ 見た目の特徴(別の ReID のモデル・画像のモデルのクエリの埋め込み)/ 組み合わせ(重みの付け方を規則で決める / 学習する) | 学習する対応付けと ReID のモデルだけ要る |
| 対応付けの手順 | 1 回の照合 / 確信度の高い検出と低い検出で 2 段に分ける(ByteTrack)/ 見失った物体との照合を分ける / 学習した照合 | 学習した照合だけ要る |
| ID の管理 | 見失った物体を残すフレームの数、新しい物体を始める条件、終える条件、カメラの動きの補正 | 要らない |
| 画像のモデル | 自作のインスタンスセグメンテーションのモデル(GTR 系・Mask2Former 系・YOLO26-seg 系・RF-DETR-Seg 系)、大きさ、確信度の閾値、枠をマスクから作るか枠の head から取るか | 要る(画像のモデルの学習) |
| データ | 歩行者(MOT17・MOT20)、同じ見た目の人の動きの多い場面(DanceTrack)、スポーツ(SportsMOT)、車載(KITTI MOTS・BDD100K MOTS)、一般の物体(VIPSeg) | 画像のモデルは要る |
| 推論の設定 | 確信度の閾値、照合の閾値、保持するフレームの数 | 要らない |
| 速さ | 追跡の手法のフレームあたりの時間、ReID の特徴の計算の有無、書き出し(ONNX)・CPU・ブラウザ | 要らない |

## ロードマップ

exp の番号は、上 3 桁がグループ、下 2 桁が通し番号(segmentation と同じ)。

| グループ | 中身 |
|---|---|
| 000xx | 基盤(データ・評価・速度の測り方・公開の手法の再現) |
| 001xx | 対応付けの手法の比較(画像のモデルを固定) |
| 002xx | 見た目の特徴(ReID)と、学習する対応付け |
| 003xx | 画像のモデルの違いと、動画のモデル(exp00502)との比較 |
| 004xx | 速さ(CPU・ブラウザ) |

### フェーズ A: 基盤(000xx)

| exp | 何をするか | 何がわかれば次に進むか |
|---|---|---|
| [exp00001](exp00001_data_and_eval/) | 使うデータと評価の指標の決定、データの入手と共通の形式への変換、データセットごとの train・val・test の役、TrackEval での評価(枠・マスク)と速度の測り方 | 正解をそのまま入れると 1、ID を入れ替える・フレームを抜くと下がることを確かめ、公式の評価のコードと値が一致する |
| exp00002 | 公開の手法の再現: 公開の検出(ByteTrack の公開の YOLOX の検出など)に、自作の SORT・ByteTrack をかけ、論文の値(MOT17 の val・DanceTrack の val)と比べる | 自作の追跡の手法が、公式と同じ検出で論文の値をほぼ再現する(追跡の手法の実装と評価が正しいことの確かめ) |
| exp00003 | 画像のモデルの準備: 自作のインスタンスセグメンテーションのモデル(segmentation の最良の構成)を、各データセットの train の役のセットで学習し、検出の精度(枠・マスクの AP、DetA)を測る | 追跡の比較に使う検出が、公開の検出と比べてどのくらいかがわかる |

### フェーズ B: 対応付けの手法の比較(001xx)

画像のモデルを固定し(exp00003 の検出)、全部の追跡の手法に同じ検出を入れて比べる。1 つの比較では 1 つの条件だけを変える。

| exp | 変えるもの |
|---|---|
| [exp00101](exp00101_association_methods/) | 規則の追跡の手法の代表(SORT・ByteTrack・OC-SORT・BoT-SORT など。候補はこの exp の README)。まず枠の IoU と動きの予測だけ(見た目の特徴なし) |
| exp00102 | 枠の IoU → マスクの IoU(インスタンスセグメンテーションのモデルを使う意味があるか。重なりの多い場面で効くか) |
| exp00103 | マスクの伝搬を手がかりに足す(McByte 型: 学習済みの SAM 2 でマスクを次のフレームに運び、照合の手がかりにする。伝搬のモデルは学習し直さない) |

### フェーズ C: 見た目の特徴と、学習する対応付け(002xx)

| exp | 変えるもの |
|---|---|
| [exp00201](exp00201_appearance_reid/) | 見た目の特徴(ReID の評価のデータ・指標の下調べはこの exp の README): 別の ReID のモデル(人の ReID で学習したもの)/ 画像のモデルのクエリの埋め込み(画像のモデルが出す物体ごとの特徴をそのまま使う。追加の計算がない)/ マスクの中の特徴の平均 |
| exp00202 | 学習する対応付け: 画像のモデルを固定し、検出の手がかり(位置・動き・見た目)から照合を学習する(CAMELTrack・TDLP 型)。MOTIP 型(検出ごとのクエリの特徴から ID を分類として予測する decoder)も、自作の GTR 系の検出の部と組み合わせて扱う: まず画像のモデルを固定して ID の decoder だけを学習し、次に公式どおり画像のモデルと一緒に学習する |

### フェーズ D: 画像のモデルの違いと、動画のモデルとの比較(003xx)

| exp | 変えるもの |
|---|---|
| exp00301 | 画像のモデル: 自作の各構成・大きさ・確信度の閾値で、追跡の手法を固定して比べる(検出の精度と追跡の精度の関係) |
| exp00302 | 動画のモデルとの比較: VIPSeg の 8 クラスで、2 段の構成の最良と exp00502 の動画のモデルを、同じ評価(動画の AP・画像 AP・HOTA・AssA)で並べる。長い隠れ・長い動画・物体の多い動画に分けて見る |

### フェーズ E: 速さ(004xx)

| exp | 変えるもの |
|---|---|
| exp00401 | フレームあたりの時間(画像のモデル・追跡の手法・ReID の特徴に分ける)、書き出し(ONNX)、CPU(1・4 スレッド)・ブラウザ |
