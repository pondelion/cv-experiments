# exp00101: 対応付けの手法の比較(規則の方式)

## 目的

画像のモデル(検出)を固定し、同じ検出に規則の追跡の手法の代表をかけて比べる。まず枠の IoU と動きの予測だけ(見た目の特徴なし)。
実装する手法ごとに、トップの README の「MOT の仕組みの書き方」の 4 項目(対応付け・見失った物体の保持・新しい物体・消えた物体)を書く。

## 候補(2026-11 時点の下調べ。値は各論文の自己申告で、こちらでは確かめていない)

学習する対応付け・マスクの伝搬・見た目の特徴の方式も、比べる相手の全体像として同じ表に並べる。この exp で扱うのは、見た目の特徴
(ReID)を使わない規則の方式だけ。ほかは「扱う exp」の列の exp で扱う(mot/README.md の計画)。

### 追跡の手法の実装

どの手法も `run_tracker.py` で保存した検出にかけて評価する(GPU は使わない。1 つのセットの追跡と評価で 10 秒前後)。手法の閾値は、
追跡の手法 × 検出の組ごとに val の役のセットで選び、test の役のセットでは 1 回だけ測る。

公式のコードとの一致の確かめ: 同じ保存した検出を、公式のコード(ifzhang/ByteTrack の `yolox/tracker/`、abewley/sort の `sort.py`、
noahcao/OC_SORT の `trackers/ocsort_tracker/`。手を入れずに動かす。numpy 2 で消えた `np.float` だけ足す)と自作の実装の両方に入れ、
各フレームの出力(ID と枠)の集まりを比べた。3 つの検出 × 3 つの val の役のセット × 3 つの手法 × 2〜3 個の閾値(val で選んだ値と
公式の値を含む)の 72 通り、合わせて約 29 万フレームで、一致しないフレームは 0。比べる前に見つかって直した違いは 4 つ(どれも直す前の
結果は使っていない。全部の結果を直した後に計算し直した):

- ByteTrack: 公式は、見失った物体を保持のフレームの数を超えて終えたフレームでも、その物体を見失った物体の並びから次のフレームまで
  除かない(並びから除く処理が、このフレームで終えた物体を記録に足す前に動く)。そのため、終えた次のフレームの照合でも同じ ID に
  戻ることがある。自作はすぐに除いていた
- SORT・OC-SORT: 組にならなかった検出の並びの順(公式は、IoU が足りずに外した組の検出を最後に足す)。新しい ID の番号の順が変わる
- 割り当て: 公式は lap(lapjv)で解く。自作は scipy で同じ最小の費用の問題を解いていたが、費用が同じ組がいくつもあるとき(ほぼ同じ
  検出が重なるときなど)の選び方と、行と列の数が違うときの扱いが lap と違う。lap が入っていれば lap を使うようにした
- SORT・OC-SORT: 予測の面積 × 縦横比が負のとき、公式は幅が NaN になってその物体を消す。自作は 0 にして残していた

#### ByteTrack

実装: `mot/lib_common/trackers/bytetrack.py`(公式の規則を読み取って書いた。MOT の仕組みの 4 項目はファイルの先頭)。

- MOT の仕組み: 対応付けは、カルマンフィルタで予測した枠と検出の IoU のハンガリアン法を 3 段で行う(確信度の高い検出 → 残った物体と
  確信度の低い検出 → 始めたばかりの物体)。見失った物体は 30 フレーム(30 fps のとき)保持し、確信度の高い検出と IoU で照合できれば
  同じ ID に戻す。照合できなかった確信度の高い検出から新しい ID を始め(確信度 ≥ track_thresh + 0.1)、保持のフレームの数を超えた物体を
  終える
- 選んだ設定: track_thresh(確信度の高い検出の閾値)だけを、検出ごとに val の役のセットで選び、他は公式の値のまま。公式の値 0.6 は
  YOLOX の確信度の分布を前提にしていて、検出のモデルが違うと確信度の分布も違う(GTR 系は低め、Mask2Former は確信度 = クラスの
  確率 × マスクの内側の確率の平均で、分布が違う)ため。track_thresh 0.9 以上は、新しい ID を始める条件(1.0 以上)を満たす検出がなく
  HOTA 0 になるので候補から外す
- KITTI MOTS: car と pedestrian を別々に追跡し、出力の物体には照合した検出のマスクを付ける。1 つのフレームの中でマスクが重なる部分は
  確信度の高い物体に割り当てる(評価がマスクの重なりを許さないため)。横長の枠を出さない条件(幅 ÷ 高さ > 1.6)は pedestrian だけに使う
  (公式のこの条件は歩行者のデータ(MOT17 など)のためのもので、横長の物体の車には使わない)

#### SORT

実装: `mot/lib_common/trackers/sort.py`(公式の abewley/sort の規則を読み取って書いた)。

- MOT の仕組み: 対応付けは、カルマンフィルタ(状態は中心・面積・縦横比と、中心・面積の速度の 7 次元)で予測した枠と検出の IoU を
  費用にしたハンガリアン法で 1 回だけ行う(IoU 0.3 未満の組は捨てる)。照合できなかった物体は max_age 1 フレームまでしか残さない
  ので、2 フレーム以上隠れた物体は再び写っても新しい ID になる。照合できなかった検出からすぐ新しい ID を始め、3 回続けて照合できた
  物体を出力する。出力の枠はカルマンフィルタで直した後の枠
- 選んだ設定: 公式は渡された検出を全部使う(確信度で選ばない)。自作の画像のモデルは確信度の低い検出が多いので、使う検出の確信度の
  下限 det_thresh を足し、val の役のセットで選ぶ(公式の値の行は 0 = 保存した確信度 0.05 以上の検出を全部使う)。ほかは公式の既定の値。
  枠の IoU は公式と同じく、画素の +1 をしない数え方(ByteTrack の公式だけ +1 をする)
- 公式の評価と同じく、出力の枠を大きさ・縦横比で選ばない

#### OC-SORT

実装: `mot/lib_common/trackers/ocsort.py`(公式の noahcao/OC_SORT の `ocsort.py`・`association.py`・`kalmanfilter.py` の規則を
読み取って書いた)。SORT に次の 3 つを足したもの:

- OCM: 照合の費用に、動きの向きの一致を足す。物体の 3 フレーム前の観測から検出への向きと、物体の動きの向きが近いほど費用を下げる
  (重み = inertia 0.2 × 検出の確信度)
- OCR: 1 段目で組にならなかった物体と検出を、予測した枠ではなく最後に観測した枠の IoU でもう一度照合する
- ORU: 見失っていた物体を再び照合できたとき、見失う前の状態に戻し、見失っていた間のフレームの枠を、最後の観測と今の観測の間の
  直線(中心・幅・高さを等間隔)で補って、カルマンフィルタの予測と更新をやり直す

- MOT の仕組み: 照合できなかった物体は max_age 30 フレームまで残し、最後に観測した枠でも照合する(OCR)ので、止まって隠れた物体は
  同じ ID に戻りやすい。照合できなかった検出から新しい ID を始め、3 回続けて照合できた物体を出力する(照合できないフレームが 1 つでも
  あると、続けて照合できた回数は 0 に戻る)。出力の枠は最後に観測した枠(検出の枠)
- 選んだ設定: 公式の既定の値(det_thresh 0.6、IoU 0.3、max_age 30、min_hits 3、delta_t 3、inertia 0.2、確信度の低い検出の 2 段目の
  照合(use_byte)なし)。det_thresh だけを val の役のセットで選ぶ。公式の評価と同じく、面積 100 以下の枠と横長(幅 ÷ 高さ > 1.6)の枠は
  出力しない(KITTI MOTS の car には横長の条件を使わない)

動作の確かめ(mot17_val、正解の枠を少し揺らして検出として入れる。HOTA / AssA / IDSW): 検出を消さないときは ByteTrack 90.6 / 90.2 / 44、
SORT 92.0 / 92.5 / 15、OC-SORT 89.6 / 89.0 / 33。検出を 30% 無作為に消すと、ByteTrack 61.1 / 59.6 / 201、SORT 16.3 / 8.5 / 1,127、
OC-SORT 32.6 / 32.7 / 118。見失った物体を 1 フレームで消す SORT は ID が切れ、OC-SORT は同じ ID に戻す。OC-SORT の DetA(32.6)が低いのは、
照合できないフレームのたびに続けて照合できた回数が 0 に戻り、また 3 回続くまで出力しないため(公式の規則どおり)。

### 分かったこと

- 追跡の手法の違い: どの検出・どのセットでも、ByteTrack の HOTA が最も高いか、ほぼ同じ。VIPSeg のフレームで学習した GTR 系の検出
  (val で選んだ閾値)では、MOT17 で ByteTrack 48.3・OC-SORT 44.3・SORT 41.8、DanceTrack で 36.8・35.1・31.3、KITTI MOTS の car で
  55.4・54.4・51.8、pedestrian で 26.5・24.1・24.2。SORT は見失った物体を 1 フレームで消すので、どこでも AssA が低く IDSW が多い
  (DanceTrack で IDSW 3,860 回、ByteTrack は 2,870 回)
- OC-SORT は、動きの補正が効くはずの DanceTrack でも ByteTrack を上回らない(VIPSeg の GTR 系の検出で HOTA 35.1 と 36.8、AssA 21.0 と
  23.6。COCO の GTR 系の検出では 36.6 と 36.3 でほぼ同じ)。上回らない原因はまだ調べていない
- 論文の値との比べ方: OC-SORT の論文(Cao ら、CVPR 2023)は、同じ検出(ByteTrack の公開した YOLOX の重み。各データセットで学習した
  もの)で比べて、MOT17 の test で ByteTrack 63.1・OC-SORT 63.2(ほぼ同じ)、DanceTrack の test で SORT 47.9・ByteTrack 47.3・
  OC-SORT 54.6(OC-SORT が 7 高い)としている。ここの結果は、MOT17 で ByteTrack と OC-SORT が近い点は論文と同じ向き(ここでは
  ByteTrack が 3〜4 高い)、DanceTrack で OC-SORT が上回らず SORT が 3〜5 低い点は論文と違う。違う点の候補は検出で、ここの検出は
  MOT のデータで学習しておらず、DanceTrack の DetA が 52〜60 と低い(論文の DanceTrack の test の DetA は SORT 72.0・ByteTrack 71.6・
  OC-SORT 80.4)。検出の違いの影響かどうかは
  まだ確かめていない(公開された検出を同じ追跡のコードにかけて論文の値が出るかを見るのが exp00002 の予定)。追跡の手法の実装は、
  上の「公式のコードとの一致の確かめ」のとおり公式のコードと出力が全部のフレームで一致している
- 公式の SORT のように検出を確信度で選ばずに全部使うと(det_thresh 0)、確信度の低い誤検出から次々に ID ができて、HOTA が大きく
  下がる(MOT17 で 41.8 → 18.5、VIPSeg の GTR 系の検出)。自作の画像のモデルの検出には、確信度の下限が要る
- セグメンテーションのモデルの違い(ByteTrack): GTR 系どうしでは、VIPSeg のフレームで学習した方が MOT17(+1.2)・DanceTrack(+0.5)・
  KITTI MOTS の pedestrian(+1.8)で高く、KITTI MOTS の car はほぼ同じ(−0.1)。Mask2Former(MinVIS の画像のモデル)は、同じ VIPSeg の
  フレームで学習した GTR 系よりどのセットでも 5〜9 低い。DetA(MOT17 で 28.9 と 38.5)だけでなく AssA(MOT17 で 54.1 と 61.9、
  DanceTrack で 19.2 と 23.6)も低く、IDSW も多い。AssA が低い原因はまだ調べていない
- 閾値を下げると、確信度の低い物体も追跡に入るので検出の当たり(DetA)が上がり、照合の相手が増えるので ID の入れ替わり(IDSW)も
  増える。GTR 系では val で選んだ値(ByteTrack 0.2〜0.5)が公式の値 0.6 より HOTA が高い(MOT17・KITTI MOTS で 6〜13)。Mask2Former は
  確信度の分布が違い、ByteTrack で 0.8〜0.85、SORT・OC-SORT で 0.8〜0.9 が最良(ByteTrack は新しい ID の確信度が閾値 + 0.1 以上
  なので 0.9 以上を使えない)
- DanceTrack は AssA が 19〜24 と低い(ByteTrack・val で選んだ閾値。MOT17 は 54〜62)。DanceTrack は服の似た人が入れ替わるように動く動画で、枠の IoU と等速の動きの
  予測だけでは ID を保ちにくい(DanceTrack を作った目的そのもの)。動きの補正(OC-SORT)や見た目の特徴(exp00201)を比べる対象になる
- KITTI MOTS の pedestrian は DetA が 18〜21 と低く(ByteTrack・val で選んだ閾値)、MOTA が負(誤検出が正解の数より多い)。原因はまだ確認していない(検出の誤りの
  内訳を見ていない)
