# exp00201: 見た目の特徴(ReID)

## 目的

追跡の対応付けの手がかりに、物体の見た目の特徴(ReID の特徴: 同じ物体なら近く、違う物体なら遠くなる埋め込み)を足し、どの特徴が
追跡に効くかを比べる。比べる特徴: 別の ReID のモデル / 画像のモデルのクエリの埋め込み(画像のモデルが物体ごとに出す特徴を
そのまま使う。追加の計算がない)/ マスクの中の特徴の平均。

## ReID の評価のデータ(2026-11 時点の下調べ)

### 論文で使われる ReID のベンチマーク

ReID の論文の表は、人では Market-1501・MSMT17(以前は DukeMTMC-reID・CUHK03 も)、車では VeRi-776・VehicleID を並べる。
どれも**複数のカメラ**の間で同じ人(車)を探すタスクで、追跡の中の ReID(1 台のカメラの中で、隠れる前と後をつなぐ)とは条件が違う。

|---|---|---|

### 追跡の論文での ReID のデータ

追跡の手法で使う ReID のモデルは、追跡のデータセットの正解の枠から切り出した画像で学習するのが一般的
(BoT-SORT は MOT17・MOT20 の正解の枠の切り出しで FastReID を学習し、重みを公開している)。ReID の良し悪しは、最後は追跡の
指標(HOTA・AssA・IDF1)で見る。BoT-SORT の論文の値では、ReID を足した分は MOT17 で HOTA +0.4、MOT20 で +0.7 と小さい。

### 手元のデータで足りるか

**追跡の中の ReID の評価は、手元のデータ(MOT17・DanceTrack・KITTI MOTS)で足りる**。正解の枠・マスクに動画を通した ID があるので、
同じ物体の切り出しの組を作れる。

- 人: MOT17(歩行者)・DanceTrack(同じ服装の人。見た目で区別しにくい難しい条件)
- 車: KITTI MOTS(車・歩行者)
- ReID の評価の作り方(案): train・val・test の役は exp00001 と同じに分け、各動画の中で、ある時刻の切り出しを問い(query)、
  ほかの時刻の切り出しを探す先(gallery)にする。すぐ隣のフレームはほぼ同じ画像で簡単すぎるので、問いと探す先の間を一定のフレーム
  以上あける(何フレームあけるかは、隠れの長さの分布を見て決める)

**決めたこと(2026-11-23)**: ReID の評価は手元のデータ(MOT17・DanceTrack・KITTI MOTS)だけで行い、ReID のベンチマークは
入手しない(データを増やさないため)。ReID の論文と同じ条件の値(複数のカメラの間の人の ReID。Market-1501・MSMT17)は出さない。

## ReID の評価の指標

| 指標 | 何を測るか | 定義 |
|---|---|---|
| Rank-1(CMC の Rank-k) | 一番近い候補が同じ物体か | 問いごとに、探す先を特徴の近い順に並べ、上位 k 個の中に正解(同じ ID)があれば当たり。その割合。Rank-1・Rank-5・Rank-10 を並べることが多い |
| mAP | 同じ物体の全部の候補を、上の方に並べられているか | 問いごとに、正解の候補の位置ごとの適合率を平均した AP を、全部の問いで平均したもの。正解が複数あるときに Rank-1 より厳しい |
| mINP | 一番見つけにくい正解の位置 | 問いごとに「正解の数 ÷ 最後の正解の順位」を、全部の問いで平均したもの(Ye ら、ReID のサーベイ(TPAMI 2021)で提案) |

論文の表は Rank-1 と mAP を並べるのが標準で、mINP は足すことがある。追跡の中の ReID としては、これに加えて追跡の指標
(AssA・IDF1・ID の入れ替わりの数)で効き方を見る(ReID の値が良くても、追跡の値が上がるとは限らないため)。
