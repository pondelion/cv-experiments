# exp00201: 見た目の特徴(ReID)を使った対応付け

## 目的

追跡の対応付けの手がかりに、物体の見た目の特徴(ReID の特徴: 同じ物体なら近く、違う物体なら遠くなる埋め込み)を足し、
次の 2 つを明らかにする。

1. **どの特徴が追跡に効くか**: 別に学習した ReID のモデル・学習なしの汎用の特徴・画像セグメンテーションモデルが出す特徴を比べる
   (画像セグメンテーションモデルの特徴で足りれば、別のモデルの計算が要らない)
2. **特徴をどう学習すると効くか**: ID ごとの分類・対照学習・ID の正解なしの自己教師あり学習・検出器の埋め込みの学習し直しなど、
   最新の方式を含む学習のしかたを比べる
3. **特徴をどう使うと効くか**: 最新の方式を含む、特徴の使い方(照合の費用への足し方・特徴の更新・特徴の変換)を比べる

exp00101(見た目の特徴を使わない規則の追跡の手法)の最良を基準にし、見た目の特徴を足した分だけを測る。

## 何をするか(手順)

| 段階 | 何をするか | 何がわかるか |
|---|---|---|
| 1 | 特徴を出すモデルを、学習のしかたの候補(下の L1〜L6)で、追跡のデータの train の役のセットで学習する | — |
| 2 | 各データセットの正解の枠から切り出した物体の画像で、特徴の候補(下の F1〜F4。学習したものと学習なしのもの)の ReID の評価(Rank-1・mAP・mINP)を測る | 追跡に入れる前に、どの特徴・どの学習のしかたが同じ物体を見分けられるか |
| 3 | exp00101 の最良の追跡の手法に、BoT-SORT の使い方(下の U1)で各特徴を足し、追跡の指標で比べる | どの特徴・どの学習のしかたが追跡に効くか(目的 1・2) |
| 4 | 段階 3 の最良の特徴に、使い方の候補(U2〜U4)を 1 つずつ替えて比べる | どの使い方が効くか(目的 3) |

1 つの比べでは 1 つの条件だけを変える。検出は exp00003 の保存した検出を全部の比べで共通に使う。閾値は val の役のセットで選び、
test の役のセットでは 1 回だけ測る(mot/README.md の方針)。

## 比べるもの

### 特徴(F)

| 記号 | 特徴 | 中身 | 追加の計算 | 選んだ理由 |
|---|---|---|---|---|
| F1 | 別に学習した ReID のモデル | 物体の切り出しの画像から特徴を出す CNN を、追跡のデータの train の役のセットの正解の切り出しで学習する。作りは BoT-SORT・Deep OC-SORT・TrackTrack が使う FastReID の SBS(公式の `Base-SBS.yml`: 非局所のブロック入りの ResNet 系 + GeM の
プーリング + BNNeck、Circle の分類の損失(交差エントロピー、ラベルの平滑化 0.1)+ triplet の損失(難しい組を選ぶ)、入力 384 × 128。
BoT-SORT の MOT17 の重みは ResNeSt-50 の sbs_S50)を自作で実装する | 検出ごとに CNN を 1 回 | 今の追跡の手法(TrackTrack(2025)まで)の標準。比べる基準 |
| F2 | 汎用の学習済みの特徴(学習なし) | 物体の切り出しの画像を、学習し直さない DINOv3 の ViT-B/16 に通した特徴 | 検出ごとに ViT を 1 回 | 学習なしで使える汎用の特徴が、F1 の代わりになるか(CLIP の特徴を DeepSORT・StrongSORT に入れて ID の入れ替わりが減ったという報告がある) |
| F3 | 画像セグメンテーションモデルのクエリの埋め込み | 検出を出した画像セグメンテーションモデル(GTR 系・Mask2Former)が、検出ごとに持つクエリの特徴をそのまま使う | なし | 追加の計算がない。DETR 系のクエリの特徴は物体の見た目を持つという主張(FastTrackTr)と、ID の学習なしでは物体ごとにまとまらないという報告(ContrastTR)がある |
| F4 | マスクの中の特徴の平均 | 画像セグメンテーションモデルの画素の特徴を、検出のマスクの中で平均する | ほぼなし | マスクを持つインスタンスセグメンテーションモデルならではの特徴。背景を含まない |

### 特徴の学習のしかた(L)

F1(別の ReID のモデル)と F3(画像セグメンテーションモデルのクエリの埋め込み)は、学習のしかたで特徴の良し悪しが大きく変わる。
学習のしかたも比べる対象にする。

| 記号 | 方式 | 年 | 中身 | 学習に使う正解 | 公式のコード |
|---|---|---|---|---|---|
| L1 | FastReID の SBS(BoT-SORT・Deep OC-SORT・TrackTrack の ReID) | 2020〜 | 物体の切り出しの分類(Circle の損失)+ triplet の損失。ID ごとの分類として学習する | 追跡のデータの ID | あり(`JDAI-CV/fast-reid`) |
| L2 | [QDTrack](https://arxiv.org/abs/2006.06664)(準密な類似の学習) | 2021(CVPR、TPAMI 2023) | 2 つのフレームの、正解の近くの多数の候補の領域どうしで、同じ物体の領域を近づける対照学習(多数の正例・負例) | 追跡のデータの ID | あり |
| L3 | [Walker](https://arxiv.org/abs/2409.17221) | 2024(ECCV) | **ID の正解なしの自己教師あり学習**: 時間方向の物体の見た目のグラフの上の random walk を、多数の正例の対照学習で最適化する。追跡の ID のラベルが要らない(枠の正解はまばらでよい) | 枠だけ(ID なし) | あり(`mattiasegu/walker`) |
| L4 | [FDTA](https://arxiv.org/abs/2512.02392) | 2025(CVPR 2026) | **検出器のクエリの埋め込みを、追跡に向くように学習し直す**: 空間・物体ごと(IoU で例の質を量る対照学習)・ID の予測の 3 つの部品を足す。検出のために学習しただけのクエリの埋め込みは、違う物体どうしも似てしまう問題を直す | 追跡のデータの ID | あり(論文に記載) |
| L5 | [CLIP-ReID](https://arxiv.org/abs/2211.13977) | 2023(AAAI) | 学習済みの CLIP を、言葉のトークンを学習する段と画像の encoder を ReID で学習する段の 2 段で ReID に合わせる | ReID の ID | あり |
| L6 | [Cluster Contrast](https://arxiv.org/abs/2103.11568) | 2022(ACCV) | **ID の正解なし**: 特徴を集団に分けて仮の ID を作り、集団の単位の記憶で対照学習する(ID なしの人の ReID の代表) | なし | あり(`alibaba/cluster-contrast`) |

F3(画像セグメンテーションモデルのクエリの埋め込み)は、学習なし(そのまま)と L4 で学習し直したものの両方を比べる。F1 は L1〜L3・L5・L6 で
学習した ReID のモデルを比べる。

調べたが選ばなかった学習の方式:

| 方式 | 年 | 中身 | 選ばない理由 |
|---|---|---|---|
| [SOLIDER](https://arxiv.org/abs/2303.17602)・LUPerson・PersonMAE | 2021〜2023 | 大量の人の画像での自己教師ありの事前学習 | 事前学習のデータ(LUPerson の 418 万枚など)と計算が大きい(PASS は ViT-B で A100 8 枚 120 時間)。学習済みの重みを F1 の初期値として使うかは L1 の結果を見て決める |
| VLA-ReID | 2026 | 動画の単位の照合として ReID を学習する | 公式のコードが見つからない |
| ReIDTrack・YOLO11-JDE | 2023・2025 | MoCo-v2 などの自己教師ありの ReID。YOLO11-JDE は検出器に ReID の枝を足す形 | ID なしの学習は L3・L6 で扱う。検出器と一緒に学習する形はこの mot の対象外(画像のモデルは固定する) |
| MOTIP | 2025(CVPR) | 検出ごとのクエリの特徴から ID を予測する decoder を学習する | 学習する対応付けなので exp00202 で扱う |

参考: 2025 年時点の人の ReID のモデルの比べ([Person Re-ID in 2025](https://arxiv.org/abs/2601.20598))では、言葉と合わせて学習したモデル
(CLIP・SigLIP2)が、ReID のために学習していないのに、別のデータの上でも強いと報告している。F2 の学習なしの特徴の候補に入れる。

### 特徴の使い方(U)

| 記号 | 方式 | 年 | 中身 | 公式のコード |
|---|---|---|---|---|
| U1 | [BoT-SORT](https://arxiv.org/abs/2206.14651) | 2022 | 追跡している物体の特徴を指数移動平均(係数 0.9)で更新する。照合の費用 = 枠の IoU の距離と、見た目の距離(cos の距離 ÷ 2)の小さい方。見た目の距離は、閾値(0.25)を超えるか、IoU の距離が閾値(0.5)を超える組では使わない(1 にする) | あり(確かめた: `tracker/bot_sort.py`) |
| U2 | [Deep OC-SORT](https://arxiv.org/abs/2302.11813) | 2023 | OC-SORT に見た目の特徴を足す。特徴の更新の係数を検出の確信度で変え(確信度の低い検出では古い特徴を多く残す)、見た目の費用の重みを、物体ごとに見た目の区別のつきやすさで変える | あり |
| U3 | [HATReID](https://arxiv.org/abs/2503.12562) | 2025(ECCV 2026) | 学習なしで特徴を変換する: 追跡している物体の過去の特徴から、物体どうしを最もよく分ける射影を、Fisher の線形判別(閉じた式で解ける)で毎回求め、特徴をその射影に通してから比べる。どの特徴・どの追跡の手法にも足せる | あり(`HELLORPG/HATReID-MOT`) |
| U4 | [TrackTrack](https://openaccess.thecvf.com/content/CVPR2025/papers/Shim_Focusing_on_Tracks_for_Online_Multi-Object_Tracking_CVPR_2025_paper.pdf) | 2025(CVPR) | 追跡している物体の側から照合を決める(Track-Perspective-Based Association)、新しい物体の始め方を追跡している物体を考えて決める(Track-Aware Initialization)。見た目の特徴は FastReID | あり(`kamkyu94/TrackTrack`) |

選ばなかった方式(調べた中で新しいもの):

| 方式 | 年 | 中身 | 選ばない理由 |
|---|---|---|---|
| [Polycepta](https://arxiv.org/abs/2606.23604) | 2026 | 見た目を、フレームごとの観測ではなく、時間をかけて推定する状態として持つ(既存の追跡の手法に足す部品) | 公式のコードが見つからない(2026-11 時点)。規則を確かめられない |
| [VLA-ReID](https://arxiv.org/abs/2607.17157) | 2026 | よく似た小さい物体が密集する場面向けに、ReID の学習を動画の単位の照合として行う | 公式のコードが見つからない。対象(小さく密集した物体)が手元のデータと違う |
| [StrongSORT](https://arxiv.org/abs/2202.13514) | 2022(TMM 2023) | DeepSORT に BoT の ReID・特徴の指数移動平均・カメラの動きの補正などを足す | 特徴の使い方は U1 とほぼ同じ |
| [CAMELTrack](https://arxiv.org/abs/2505.01257)・MOTIP | 2025 | 見た目を含む手がかりの照合を学習する | 学習する対応付けなので exp00202 で扱う |

## 評価

### ReID の評価(段階 1)

| 指標 | 何を測るか | 定義 |
|---|---|---|
| Rank-1 | 一番近い候補が同じ物体か | 問い(query)ごとに、探す先(gallery)を特徴の近い順に並べ、1 番目が正解(同じ ID)なら当たり。その割合 |
| mAP | 同じ物体の全部の候補を、上の方に並べられているか | 問いごとに、正解の候補の位置ごとの適合率を平均した AP を、全部の問いで平均したもの |
| mINP | 一番見つけにくい正解の位置 | 問いごとに「正解の数 ÷ 最後の正解の順位」を、全部の問いで平均したもの([Ye ら TPAMI 2021](https://arxiv.org/abs/2001.04193)) |

- データ: 手元の追跡のデータ(MOT17・DanceTrack・KITTI MOTS)の正解の枠の切り出し。ReID のベンチマーク(Market-1501・MSMT17 など。
  複数のカメラの間で人を探すタスクで、追跡の中の ReID とは条件が違う)は使わない(2026-11-23 に決めた)
- 問いと探す先: 動画ごとに、ある時刻の切り出しを問い、同じ動画のほかの時刻の切り出しを探す先にする。すぐ隣のフレームは
  ほぼ同じ画像で簡単すぎるので、問いと探す先の間を一定のフレーム以上あける(何フレームあけるかは隠れの長さの分布を見て決める)
- train・val・test の役は exp00001 と同じ。F1 の学習は train の役のセットだけで行う

### 追跡の評価(段階 2・3)

exp00101 と同じ: TrackEval の HOTA・DetA・AssA・IDF1・MOTA・IDSW(マスクのデータはマスクの IoU)。見た目の特徴が効くのは主に
対応付けなので、AssA・IDF1・IDSW を主に見る。

## 調査: ReID のベンチマーク(使わないもの、参考)

| データセット | 中身 | 入手(確かめたこと) |
|---|---|---|
| Market-1501 | 人 1,501 人・6 台のカメラ。学習 12,936 枚・テスト 19,732 枚 | 公式の配布のページのドメイン(liangzheng.org)は失効していて、公式からは入手できない |
| MSMT17 | 人 4,101 人・15 台のカメラ・126,441 枚。今の人の ReID の主な大きいベンチマーク | 作者(北京大学)への利用の申し込みが要る |
| DukeMTMC-reID | 人 1,404 人・8 台のカメラ | 2019 年に Duke 大学が取り下げた([Duke Chronicle](https://dukechronicle.com/article/2019/06/duke-university-facial-recognition-data-set-study-surveillance-video-students-china-uyghur)) |
| VeRi-776・VehicleID | 車の ReID | どちらも作者への申し込みが要る |

追跡の論文の ReID のモデルは、追跡のデータの正解の枠の切り出しで学習するのが一般的(BoT-SORT は MOT17・MOT20 の切り出しで
FastReID を学習)。BoT-SORT の論文の値では、ReID を足した分は MOT17 で HOTA +0.4、MOT20 で +0.7 と小さい。DanceTrack は
同じ服装の人が多く、見た目だけでは区別しにくい。
