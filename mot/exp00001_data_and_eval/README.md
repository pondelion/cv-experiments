# exp00001: 使うデータと評価の指標

## 目的

mot/ の全部の exp で使う、データセット・評価の指標・データセットごとの train・val・test の役を決める。
あわせて、論文で一般的に使われるベンチマークと指標を調べてまとめる(使わないものも、選んだ理由がわかるように残す)。

SportsMOT を並べる。マスクの追跡(MOTS)は KITTI MOTS・MOTS20・BDD100K MOTS。ダウンロードのサイズは、公式の配布元

## 論文で使われる指標

計算は、どれも公式の TrackEval のコードで行うのが標準。

| 指標 | 何を測るか | 主に使うデータ |
|---|---|---|
| HOTA | 見つけ方(DetA)と ID のつながり(AssA)の相乗平均を、IoU の閾値 0.05〜0.95 で平均したもの。今の主な指標 | 全部(MOTS はマスクの IoU で計算する) |
| DetA・AssA | HOTA を分けたもの。DetA = 各フレームで見つけられたか、AssA = 対応した物体どうしが動画を通して同じ ID で続く割合 | DanceTrack・SportsMOT の表でよく並べる |
| IDF1 | ID を通した対応の F1(ID の保ちやすさ) | MOT17・MOT20・DanceTrack など |
| MOTA | 見逃し・誤検出・ID の入れ替わりを合わせて数えた以前からの指標(見つけ方に強く左右される) | MOT17・MOT20(論文の表に今も載る) |
| IDSW | ID が入れ替わった回数 | MOT17・MOT20 |
| sMOTSA | マスクの IoU で重み付けした MOTA | KITTI MOTS・MOTS20(以前の主な指標。KITTI MOTS は今は HOTA で順位を付ける) |
| mHOTA・mMOTA・mIDF1・TETA | クラスごとに出して平均したもの。TETA はクラスの当て方と追跡を分けて測る指標 | BDD100K・TAO |

## 使うデータ(案)

必要なものだけを入手する。選ぶときの観点は 3 つ。

1. 自作の追跡の手法が正しく動くことを、論文の値で確かめられるか(最もよく使われるベンチマーク)
2. 対応付けの手法の差が出やすいか(対応付けを比べるのが mot/ の中心)
3. インスタンスセグメンテーションのモデル(マスク・複数のクラス)を使う意味が出るか、動画のモデル(exp00502)と並べられるか

| データセット | 使う | 理由 | サイズ |
|---|---|---|---|
| MOT17 | 使う | 観点 1: 最もよく使われ、公開の手法の値が一番多い。自作の追跡の手法の再現の確かめに使う。小さい | 5.86 GB |
| DanceTrack(train・val だけ) | 使う | 観点 2: 見た目で区別しにくく動きも大きいので、対応付けの差が一番出る。公開の val で評価できる。test は正解がないので落とさない | 11.1 GB |
| BDD100K MOTS | 使いたかったが入手できない(下の「入手できなかったデータ」) | 観点 3: マスクの追跡で、クラスが 8 つあり(segmentation の 8 クラスと人・車・自転車などが重なる)、公開の val で評価できる | 5.9 GB |
| VIPSeg | 使う(入手済み) | 観点 3: exp00502 の動画のモデルと、同じセット・同じ評価で並べる | — |
| MOTS20 | 必要になったら | MOT17 の一部の動画のマスクで、歩行者のマスクの追跡を MOT17 と同じ動画で見られる。小さい(0.69 GB)が、動画が 4 本だけ | 0.69 GB |
| KITTI MOTS | 使う(BDD100K MOTS の代わり) | 観点 3: 車載のカメラのマスクの追跡(車・歩行者の 2 クラス)。公式の順位も HOTA。test の正解は非公開なので、training を分けて使う | 15.8 GB |
| MOT20・SportsMOT | 使わない | MOT20 は MOT17 と同じ歩行者で密集だけが違う。SportsMOT はスポーツに限った場面で大きい(36.5 GB)。対応付けの比較は DanceTrack で足りる | — |
| TAO | 使わない | 大きすぎる(約 114 GiB)。オープンボキャブラリーの追跡をするときに考える | — |
| CrowdHuman | 後で決める | 人の検出器の学習に足す慣例があるが、追跡の比較では検出を固定するので、まずは不要。人の検出が弱いとわかったら考える | 未確認 |

合計は約 33 GB(MOT17 + DanceTrack の train・val + KITTI MOTS)。

## データセットごとの役(案)

| データセット | train | val(設定の値・最良の重みの選択) | test(最終の値。何かを選ぶのには使わない) |
|---|---|---|---|
| MOT17 | train の各動画の前半 | train の各動画の後半の一部 | train の各動画の後半の残り。論文の値と比べるときは、慣例の「後半全部」でも出す(下の注) |
| DanceTrack | train | train から分けた数本 | val(公式) |
| KITTI MOTS | MOTS の論文の train 12 本 | train 12 本から分けた数本 | MOTS の論文の val 9 本 |
| VIPSeg | exp00502 と同じ | exp00502 と同じ(dev) | exp00502 と同じ(val) |

注: 論文の MOT17 の val の値(ByteTrack 以降の慣例)は、train の後半で設定の値も選んでいることが多い。公開の手法の値を再現して
確かめるときだけ、その慣例と同じ分け方で測り、自作の比較は上の分け方(val と test を分ける)で行う。

## 結果

### 入手したデータの確認(2026-11-23)

置き場所: `datasets/mot17/MOT17/`・`datasets/dancetrack/{train1,train2,val}/`(元の zip は、展開して中身を確かめた後に消した)。
zip はどれも配布元のサイズと一致し、`unzip -t` で壊れていないことを確かめた。

| データセット | 部分 | 動画 | フレーム | 解像度・fps | 正解の枠 | ID の数(動画ごとの和) |
|---|---|---|---|---|---|---|
| MOT17 | train | 7 本 | 5,316 | 1920×1080・25〜30fps(MOT17-05 だけ 640×480・14fps) | 112,297(歩行者・評価に使う印のもの) | 546 |
| MOT17 | test | 7 本 | 5,919 | 同上(MOT17-06 が 640×480) | なし(非公開) | — |
| DanceTrack | train | 40 本 | 41,796 | 1920×1080・1280×720 など・20fps | 348,930 | 419 |
| DanceTrack | val | 25 本 | 25,508 | 同上 | 225,148 | 273 |

- **MOT17**: 動画ごとに DPM・FRCNN・SDP の 3 つの版があるが、画像と正解は同じ(公開の検出 `det/det.txt` だけが違う)。
  正解 `gt/gt.txt` は `フレーム, ID, 左, 上, 幅, 高さ, 評価に使う印, クラス, 見えている割合`。クラス 1 が歩行者で、評価は
  クラス 1・印 1 だけを使う(ほかのクラス(車・静止した人・反射など)の枠も正解のファイルに入っていて、TrackEval はそれらに
  重なる予測を誤検出に数えない)
- **DanceTrack**: 正解の形式は MOT17 と同じで、全部の枠がクラス 1・印 1・見えている割合 1(人だけ)。各動画の画像の数は seqinfo.ini の
  フレーム数と一致した
- 動画の長さ: MOT17 は 1 本 525〜1,050 フレーム、DanceTrack は 1 本 1,000 フレーム前後

**KITTI MOTS**(BDD100K MOTS の代わりに入手。`datasets/kitti_mots/`。zip は配布元のサイズと一致し、`unzip -t` で壊れていない)

| 部分 | 動画 | フレーム | 正解のマスク | 物体の数(動画ごとの ID の和) |
|---|---|---|---|---|
| training | 21 本 | 8,008 | 車 26,860・歩行者 11,415(+ 無視する領域 7,743) | 749 |
| testing | 29 本 | 11,095 | なし(非公開) | — |

- 画像は `training/image_02/{動画}/{フレーム}.png`(KITTI tracking の左のカラーのカメラ)。正解は 2 つの形式で同じ中身:
  `instances/{動画}/{フレーム}.png`(画素の値 = クラス × 1000 + ID)と `instances_txt/{動画}.txt`
  (1 行 = `フレーム ID クラス 縦 横 RLE`。クラス 1 = 車・2 = 歩行者、ID 10000・クラス 10 = 評価で無視する領域)
- 正解の PNG の数は各動画の画像の数と一致した(`instances/0000/` には注釈の道具の隠しファイル `.history.voigtlaender` が 1 つ
  余分にあるが、データではない)

### 評価のセットと評価の仕組みの確認(`check_eval.py`)

評価のセット(上の「データセットごとの役」)を `mot/lib_common/sets.py` で作り、TrackEval が読む形の正解を `datasets/mot_sets/{セット}/`
に書き出した。役の細部: MOT17 は val = 後半の前の半分・test = 後半の残り(各動画の中を時間で分ける)。DanceTrack の val は公式の
train から seed 0 で選んだ 8 本(dancetrack0006・0044・0051・0061・0062・0066・0075・0080)。KITTI MOTS の val は公式の train 12 本から seed 0 で選んだ 3 本(0000・0011・0020)。評価は `mot/lib_common/evaluate.py`
(TrackEval の MotChallenge2DBox・KittiMOTS。公式の MOTChallenge・DanceTrack・KITTI MOTS の評価と同じ設定)。

答えのわかる追跡の結果で、評価が正しく動くことを確かめた(値は %。IDSW は回数):

| セット | 正解そのまま: HOTA / IDF1 / MOTA | ID を真ん中で付け替え: HOTA / DetA / AssA / IDF1 / IDSW | 1 フレームおきに消す: HOTA / DetA / IDF1 |
|---|---|---|---|
| mot17_train | 100 / 100 / 100 | 81.0 / 100 / 65.6 / 68.0 / 136 | 50.1 / 50.1 / 66.7 |
| mot17_val | 100 / 100 / 100 | 77.5 / 100 / 60.1 / 61.9 / 132 | 50.1 / 50.1 / 66.8 |
| mot17_test | 100 / 100 / 100 | 77.0 / 100 / 59.2 / 61.8 / 135 | 50.1 / 50.1 / 66.8 |
| mot17_valhalf | 100 / 100 / 100 | 81.3 / 100 / 66.1 / 68.5 / 124 | 50.1 / 50.1 / 66.8 |
| dancetrack_train | 100 / 100 / 100 | 71.4 / 100 / 51.0 / 52.4 / 329 | 50.1 / 50.1 / 66.7 |
| dancetrack_val | 100 / 100 / 100 | 73.3 / 100 / 53.7 / 55.7 / 64 | 50.0 / 50.0 / 66.7 |
| dancetrack_test | 100 / 100 / 100 | 71.8 / 100 / 51.6 / 54.0 / 265 | 50.0 / 50.0 / 66.7 |
| kitti_mots_train(車 / 歩行者) | 100 / 100 / 100 | 95.2 / 100 / 90.7 / 91.8 / 21(車)、92.9 / 100 / 86.3 / 89.1 / 14(歩行者) | 50.0 / 50.0 / 66.6 |
| kitti_mots_val(車 / 歩行者) | 100 / 100 / 100 | 94.2 / 100 / 88.7 / 91.1 / 23(車)、100(歩行者) | 50.0 / 50.0 / 66.7 |
| kitti_mots_test(車 / 歩行者) | 100 / 100 / 100 | 88.1 / 100 / 77.6 / 79.8 / 34(車)、86.1 / 100 / 74.1 / 79.5 / 17(歩行者) | 50.0 / 50.0 / 66.6 |

- 正解をそのまま渡すと全部の指標が 100(IDSW 0)。ID を付け替えると DetA は 100 のまま AssA・IDF1 だけが下がり、IDSW が数えられる。
  1 フレームおきに消すと DetA が約 50 に下がる(HOTA の AssA も、対応した組の見逃しを数えるので約 50 になる)
- kitti_mots_val の歩行者だけ、付け替えても 100: この 3 本の歩行者は、どれも動画の真ん中より前か後だけに写っていて、付け替えが
  1 本の追跡の ID を丸ごと変えるだけになるため(ID の入れ替わりが起きない)。kitti_mots_val の歩行者は 78 フレームと少ないので、
  歩行者の設定の値を選ぶには弱い(車で選ぶか、必要なら val の本数を増やす)
- TrackEval は numpy 2 で消えた `np.float` などをまだ使っているので、`evaluate.py` の import の前にその名前を Python の型として足す
  (TrackEval のコードは変えない)

  ページ(`bdd-data.berkeley.edu`)はアカウントでのログインが要る。GitHub の issue でも 2025〜2026 年にダウンロードできない報告が
  続いている。Hugging Face の非公式のコピーには、MOTS(seg_track_20)を含むものが見つからなかった。代わりに KITTI MOTS を入手した(上)
