# exp00501: 動画の評価の基盤と、比較対象の基準

## 目的

動画の段階(005xx)のすべての exp で使う、データセット・評価のセット・評価の仕組み・推論速度の測り方を作る。
あわせて、公開されている学習済みのモデルをそのまま評価し、スクラッチの実装の目標になる参照点を作る(画像の段階の exp00001 と同じ役割)。

## 方針

タスクは**動画インスタンスセグメンテーション**: 各フレームで物体を全部見つけてクラスとマスクを付け、同じ物体には動画を通して同じ ID を
付ける。動画のセグメンテーションのデータで、動画のセグメンテーションのモデルを学習する。クラスはデータセットのクラスをそのまま使う。

方式は次の軸で分ける。

| 軸 | 分け方 | この段階での扱い |
|---|---|---|
| 1. クラス | 決まったクラス / オープンボキャブラリー(クラスを文章で与える) | **決まったクラスを主にする**。オープンボキャブラリーの方式(SAM 3 など)も、クラスを決めた部分(物体の見つけ方・追跡の仕組み)は流用できるので、使える部分は取り込んで確かめる |
| 2. セグメンテーションのモデル | 画像のモデル(フレームを独立に扱う)/ 動画のモデル(前のフレームのクエリ・特徴・記憶を次のフレームで使い、フレーム間の一貫性も学習する) | **動画のモデルを対象にする**。画像のモデルは基準(下の 2 × 2 の表) |
| 2'. MOT の仕組み | 持たない(隣のフレームへの引き継ぎ・照合だけで、クエリの番号などがそのまま ID)/ 持つ(動画全体で一意の ID の管理: 新しい物体・消えた物体・隠れた後の再出現の判定を含む) | **両方**。持たない方式は、実用には MOT の仕組みを足す必要があるので、足した組み合わせも比べる |
| 3. 大きさ | 精度重視(大きめの backbone)/ 軽量・速度のバランス(exp00104・exp00105 の軽い構成) | 両方。画像の段階と同じく分けて比べる |
| 4. フレームの処理の仕方 | online(過去のフレームだけで、1 フレームずつ出す)/ offline(区間・動画の全体を見てから出す) | online を主にする(実時間・エッジで動かすのに要る)。offline は精度の参考 |
| 5. 学習に要る正解 | 動画の正解が要る / 画像の正解だけで学習できる(フレームを独立に扱う) | 動画の正解で学習する。画像だけで学習する方式は、フレーム間の学習の効果を測る基準に使う |
| 6. 入力で与えるもの | なし(物体を全部見つける)/ 最初のフレームのマスク・点(SAM 2 の追跡のタスク)/ 文章 | 最後の出力は「なし」のタスク(物体を全部見つける)で測る。**マスクを与えて追う方式(SAM 2・Cutie など)も対象にする**: 基準のフレームで画像のインスタンスセグメンテーションをかけ、その出力のマスクを伝搬の入力にする(新しく出る物体は、間隔をおいた画像のインスタンスセグメンテーションで見つけて、伝搬している物体と照らして足す。DEVA・SAM 3 と同じ組み立て)。伝搬の部も、ほかの方式と同じ VIPSeg で学習する(VIPSeg の正解は全フレームの物体ごとのマスクと動画を通した ID を持つので、「あるフレームのマスク → 後のフレームの同じ物体のマスク」の組がそのまま作れる) |

## データセット

置き場所と形式は [datasets/README.md](../../../datasets/README.md)。

| データセット | クラス | 量 | 正解 | 使い方 | 状態 |
|---|---|---|---|---|---|
| VIPSeg | 124(物体 58・背景 66。物体には動画を通した ID が付く。動画のパノプティック) | train 2,806 本・66,767 フレーム、val 343 本・8,255 フレーム(test 387 本は正解なし) | train・val は全フレームにマスク | 決まったクラスの主な学習・評価(物体の 58 クラスだけを取り出す) | 取得済み |
| YouTube-VIS 2021 | 40 | 3,859 本(train 2,985)、物体 8,171、マスク約 23 万 | train だけ公開。手元では train を分けて評価する | 決まったクラスの標準の比べ方 | 公式の配布の登録(CodaLab)が通らず、未取得 |
| OVIS | 25(隠れが多い) | 901 本 | train だけ公開 | 隠れへの強さ | 同上 |
| LV-VIS | 1,196 | train 3,076 本・70,009 フレーム、val 837 本 | val まで公開 | オープンボキャブラリーの評価 | 取得済み |

### VIPSeg の中身(確認した値)

- 1 本あたりのフレーム: train 中央値 15(最小 4・最大 81)、val 中央値 20(最小 5・最大 46)
- 物体の 58 クラスごとの動画の数: train 中央値 45 本(最小 10: gun)、val 中央値 7 本(10 本未満が 38 クラス)。val は小さいので、
  クラスごとの AP はぶれが大きい
- 物体: train 24,486 個(40% が person)、val 3,058 個。物体は動画のほとんどのフレームに写る(写っているフレームの割合の中央値 ほぼ 1.0)
- マスクは 16 ビットの PNG で、画像と大きさが違うフレームはない
- val に、背景のクラスの ceiling が物体として 1 個ある。変換では物体の 58 クラス以外を除く

### LV-VIS の中身(確認した値)

- 1 本あたりのフレーム: train・val とも中央値 24(5fps で約 5 秒)。90% の動画は 30 フレーム以下
- 使われているクラス: train 1,022(クラスあたりの動画は中央値 3 本、1 本だけが 330 クラス)、val 652
- 注釈は、人が多角形で付けたマスクを動画のモデル(STCN)で次のフレームに伝え、人が直す手順(論文)。公式によると train は網羅的には
  注釈されていない
- 正解の壊れ: 画像の欠け・大きさの違いはなし。空のマスク 3 枚(34 万枚のうち)。同じフレームの物体の組の 9% で、小さい方の半分以上が
  重なる(person と服・小物のような全体と部分の両方に注釈があるためと見ている。クラスの組は数えていない)
- train と val で最初のフレームが同じ動画が 2 本ある(使うときは除く)

## この exp で作るもの(005xx の全部の exp・mot/ でも使う基盤)

| 部品 | 中身 | 置き場所 |
|---|---|---|
| 共通の動画の正解の形式 | どのデータセットも、YouTube-VIS と同じ形(動画ごとのフレームの並び + 物体ごとのフレームごとのマスク(RLE)+ クラス + 動画を通した ID)に変換する。クラスは名前の文字列も持たせ、オープンボキャブラリーの評価(学習で見るクラス・見ないクラスの区分)にも使えるようにする | `datasets/sets/`(変換のコードは `lib_common/`) |
| データセットの変換 | VIPSeg(物体の 58 クラスを取り出す。背景のクラスも、パノプティックの評価用に別に残す)・LV-VIS(重複の 2 本を除く)・YouTube-VIS / OVIS(入手できたら) | 同上 |
| 評価のセットの分け方 | 公式の val は節目の評価に使い、学習の途中の評価・最良の重みの選択には train から分けた部分を使う(画像の段階と同じく、評価のセットへの過適合を防ぐ)。正解が非公開のデータセット(YouTube-VIS・OVIS)は train を分けて作る | 同上 |
| 学習のデータの読み込み | 動画から区間(連続した数フレーム)を取り出す読み込み・区間全体で同じ変換をかけるデータ拡張。方式によらず共通にする | `lib_common/` |
| 評価の指標 | 下の表 | `lib_common/` |
| 推論速度の測り方 | フレームあたりの遅延(online の方式。最初のフレームと、記憶がたまった後で分ける)・長い動画での GPU のメモリ・物体の数による変化 | `lib_common/` |
| 予測の見本の動画・画像 | 正解と予測の並べた見本(ID ごとに色を固定して、追跡の切れ・入れ替わりが目で見えるようにする) | 各 exp の `results/samples/` |

### 評価の指標

論文で一般的に使われる指標を、タスクごとに調べてそろえた。優先度は画像の段階と同じく、**A** = 主な指標(全 exp の結果の表に
必ず載せる)、**B** = 各 exp の README に載せて差の理由を見るのに使う、**C** = 必要なときに見る。

**動画インスタンスセグメンテーションの指標**(YouTube-VIS・OVIS・LV-VIS の論文の表の標準。VidEoMT・DVIS・MinVIS・CTVIS なども
この形で出す)

| 優先度 | 指標 | 定義 | 何を見るか | 実装 |
|---|---|---|---|---|
| A | 動画の AP(AP@[0.50:0.95]) | 予測の物体と正解の物体の IoU を、動画の全フレームの交わりの和 ÷ 合わせた領域の和で計算し(どのフレームで ID が切れても下がる)、COCO と同じく IoU の閾値 0.50〜0.95 の 10 個とクラスで平均した AP。1 本の動画で 1 クラスあたり上位 100 個まで | マスク・クラス・追跡をまとめた主な指標 | 済み(`lib_common/video_eval.py`) |
| A | AP50・AP75 | IoU の閾値 0.5・0.75 だけの AP | 大まかに当たるか・形まで合うか | 済み |
| A | AR1・AR10 | 1 本の動画で 1 クラスあたり上位 1 個・10 個まで出したときの再現率(IoU の閾値 10 個とクラスで平均) | 取りこぼしの少なさ。AR1 は 1 本に 1 つしかいない物体を当てられるか | 済み |
| B | APs・APm・APl | 物体の大きさ(全フレームの平均の面積)で分けた AP。YouTube-VIS の API の区切り(128²・256² 画素)を使う | 小さい物体に弱いか | 済み |
| B | クラスごとの AP | クラスごとの動画の AP | 苦手なクラス | 済み |
| C | 長い動画の AP(YouTube-VIS 2022 の AP_L・AR_L) | 長い動画(YouTube-VIS 2022 で足された 141 本)だけで出した AP・AR | 長い動画で追跡が保てるか | 未(長い動画のセットを使うとき) |
| B | オープンボキャブラリーの AP(LV-VIS の AP・AP_b・AP_n) | 全部のクラスの AP と、学習で見たクラス(base)・見ないクラス(novel)に分けた AP | 学習で見ないクラスに広がるか | 未(同じ計算をクラスの区分で分けるだけ) |

**動画のパノプティックセグメンテーションの指標**(VIPSeg の公式の指標。VIPSeg の論文の表は VPQ・VPQ^Th・VPQ^St・STQ を並べる)

| 優先度 | 指標 | 定義 | 何を見るか | 実装 |
|---|---|---|---|---|
| B | VPQ | 動画を長さ k フレームの区間に区切り、区間の中で予測と正解の物体を、区間を通した IoU が 0.5 を超えるかで対応させて PQ を計算し、k = 0・5・10・15 で平均したもの(k = 0 は 1 フレームの PQ) | 背景のクラスも含めた、画素の分け方と追跡。VIPSeg で公開の方式の値と比べられる | 未(公式のコードと合わせる) |
| B | VPQ^Th・VPQ^St | VPQ を物体のクラス(things)と背景のクラス(stuff)に分けて平均したもの | 物体だけの出来(手元のモデルは物体の 58 クラスだけを出すので、比べるのは VPQ^Th) | 未 |
| C | STQ(= √(AQ × SQ)) | AQ = 同じ物体の画素がフレームを通して同じ ID になっているか(クラスによらない)、SQ = 全部のクラスの画素の mIoU(ID によらない)。その相乗平均 | 追跡と画素の分け方を分けて見る | 未 |

**追跡の診断の指標**(MOTS(KITTI MOTS・MOTS20)の標準。TrackEval のコードで計算する。mot/ と共通にする)

| 優先度 | 指標 | 定義 | 何を見るか | 実装 |
|---|---|---|---|---|
| B | HOTA・DetA・AssA | HOTA = √(DetA × AssA) を、マスクの IoU の閾値 0.05〜0.95 で平均したもの。DetA = フレームごとの見つけ方の正しさ、AssA = 対応した物体どうしが動画を通して同じ ID で続く割合。KITTI MOTS は 2021 年から HOTA で順位を付ける | 動画の AP が下がった原因が、各フレームの見つけ方なのか、フレーム間の対応付けなのかを分ける | 未 |
| C | LocA | 対応した物体どうしのマスクの IoU の平均 | マスクの形の正確さ | 未 |
| C | IDF1・ID の入れ替わりの数(IDSW)・sMOTSA | IDF1 = ID を通した対応の F1、IDSW = 追っている物体の ID が変わった回数、sMOTSA = マスクの IoU で重み付けした MOTA(KITTI MOTS の以前の主な指標) | ID の切れ・入れ替わりの数そのもの。古い論文の値と比べる | 未 |
| A | 画像 AP(image_AP・image_AP50・image_AP75) | 各フレームを 1 枚の画像とみなし、画像の段階と同じ COCO の mask AP を測る(物体の ID は使わない。動画のモデルは、動画の AP と同じ予測をフレームごとに分け、スコアは動画の予測のスコアのまま) | フレームごとのインスタンスセグメンテーションの精度。動画の AP は動画を通した物体ごとに 1 回だけ対応させるので、フレームごとの良さが追跡の影響に埋もれやすい。画像のモデル(フレーム独立)と同じ土台で並べられる | 済み(`lib_common/video_eval.py` の `evaluate_frames`。正解をそのまま入れると 1.0、ID を入れ替えても変わらないことを確かめた) |

**マスクを与えて追う伝搬の部の指標**(DAVIS・YouTube-VOS・MOSE の論文の表の標準の計算。SAM 2・Cutie・XMem などもこの形で出す。
ここでは VIPSeg の val で、各物体が最初に写るフレームの正解のマスクを与えて測る)

| 優先度 | 指標 | 定義 | 何を見るか | 実装 |
|---|---|---|---|---|
| B | J&F | J = 物体ごと・フレームごとの領域の IoU の平均、F = 輪郭の一致度(輪郭の画素の適合率と再現率の F 値)の平均。その 2 つの平均 | SAM 2 型・DEVA 型の伝搬の部だけの出来(正解のマスクを与えるので、画像のインスタンスセグメンテーションの誤りを除ける) | 未(DAVIS の公式の評価のコードと同じ計算にする) |
| C | J・F | 上の 2 つを分けたもの | 領域と輪郭のどちらで落ちているか | 未 |

使わない指標: 動画の意味のセグメンテーション(VSPW)の mIoU・VC(フレーム間の予測の一貫性)は、物体を分けずにクラスだけを
付けるタスクのもので、物体ごとのマスクと ID を測れないので使わない。

公開の方式の値と比べるときは、公式の評価のコード(YouTube-VIS の API、VIPSeg の VPQ・STQ のコード、TrackEval)と同じ値になる
ことを確かめてから使う(VPQ の k の取り方は論文によって 0 と 1 が混ざるので、公式のコードの取り方に合わせる)。

計算の確かめ: 正解をそのまま予測として入れて 1 になること、ID を入れ替える・フレームを抜くと下がることを、指標ごとに確かめる。
公式の評価のコード(YouTube-VIS の API、VIPSeg の VPQ のコード)がある指標は、同じ予測で値が一致することも確かめる。

## 比較対象の基準

公開されている学習済みのモデルを、学習し直さずに評価して、スクラッチの実装の目標・参照点にする。決まったクラス・オープンボキャブラリーの
どちらも入れる。

| 候補 | 種類 | 評価のしかた | 備考 |
|---|---|---|---|
| 公開の重みがある決まったクラスの方式(DVIS++・DVIS-DAQ・CAVIS・VidEoMT など) | 決まったクラス | VIPSeg で学習した公開の重みがあれば、VIPSeg の val でそのまま評価する(VPQ と、物体の部分の動画の AP) | 公開の重みの有無・ライセンスを確かめる |
| SAM 3 / SAM 3.1 | オープンボキャブラリー | クラス名を文章で与えて、VIPSeg・LV-VIS の val で評価する | 学習と同時に動かせない(GPU のメモリ)ので、学習の合間に評価する |
| そのほかのオープンボキャブラリーの方式(OVFormer・TROY-VIS など) | オープンボキャブラリー | LV-VIS の val で評価する | 公開の重みの有無を確かめる |
