# instance_segmentation: インスタンスセグメンテーションのスクラッチ実装と合成データ

インスタンスセグメンテーション(画像の中の物体を 1 つずつ見分けて、クラスとマスクを出す)のモデルをスクラッチで実装し、
**人手のラベルを使わない合成データだけで学習する**方法を、段階的に検証していく。

最終的な目標は 2 つ。

1. スクラッチ実装のモデルを、最新の論文・公開モデルと同じかそれ以上の精度・速度まで伸ばす
2. 合成データで学習する方法を確立する(インスタンスマスクがあれば検出の枠も作れるので、検出など他のタスクにも使い回せる形にする)

## 方針

- **モデル**: フルスクラッチで実装する。最新の公開実装は、実装の参考にするのと、比較対象としてそのまま動かすのに使う。
  モデルの構成(アーキテクチャ)の比較は、データの比較と並ぶ一番上の観点
- **学習データ**: 基本は合成データ(生成モデルで画像を作り、正解ラベルも自動で用意する)。
  実データ(COCO train の人手ラベル)は、上限の基準と、モデルの構成を論文の値と比べるときにだけ使う。
  正解ラベルは出どころで ① 生成だけ・② 疑似ラベル・③ 組み合わせに分け、混ぜずに比べる(「正解ラベルの作り方の分類」の節)
- **認識モデル・判定モデル**: ② ③ で、既存のモデル(SAM 3 など)での疑似ラベルと、画像の判定モデル(decision model。選択肢ごとの
  較正された確率を返すモデル)での検品・誤りの原因の分類に使う
- **評価データ**: 公開されている、ラベル付きのベンチマーク。複数のデータセットで評価して、特定のデータセットの見た目に寄っていないかを見る
- **指標**: 精度が第一。推論の速さ(書き出し・量子化・蒸留・ブラウザでの実行)も本格的に検証し、最後に精度と速度のトレードオフの図にする
- **クラス**: まずは Pascal VOC の 20 クラス(COCO の 80 クラスに全部含まれる)。比較の実験の基本は、そのうちの 8 クラス(1 回の学習を
  短くするため。「計画の見直し」の節)。必要になった段階で COCO の 80 クラスに広げる。
  後でクラスを決めないオープンボキャブラリーの実験もするので、データはクラス名を文字列で持ち、語彙を広げて作り直せる形にする

## 比較の軸

| 軸 | 中身の例 | 学習し直し |
|---|---|---|
| モデルの構成 | 1 段・アンカーなし + マスクの原型の係数(YOLACT・YOLO-seg 系)/ 2 段(Mask R-CNN 系)/ 動的な畳み込み(CondInst・SOLOv2 系)/ クエリ方式(Mask2Former・Mask DINO 系)/ 速いクエリ方式(RF-DETR-Seg・LW-DETR 系) | 要る |
| 部品の実装 | backbone・neck・ヘッドごとに、簡略版 → 論文相当 → 別の構成への置き換え。正解の割り当て(IoU の閾値 / 予測の良さで動的に決める / ハンガリアン法)、マスクの損失(BCE・Dice・点を選んで計算する損失) | その部品から後 |
| 外部モデル | backbone の事前学習の重み: なし / ImageNet(ResNet・ConvNeXt)/ 自己教師あり学習(DINOv2・DINOv3)。固定する / 全部学習する / LoRA | 要る |
| 学習データ | 実データ(上限)/ 正解ラベルの作り方(下の「正解ラベルの作り方の分類」の ①生成だけ・②疑似ラベル・③組み合わせと、その中の方法)、枚数、文章の多様性、生成モデル、方式の混合、少量の実データとの併用 | 要る |
| 学習の仕方 | 学習の長さ、入力の解像度・複数の解像度、データ拡張(大きく拡大縮小・切り貼り)、EMA、損失の重み | 要る |
| 推論の設定 | 入力の解像度、スコアの閾値、重なりの除去(NMS)の有無と閾値、出す数の上限 | 要らない |
| 推論の最適化 | bf16・torch.compile → ONNX Runtime → TensorRT(fp16・INT8)→ 量子化を考えた学習 → 蒸留・枝刈り → ブラウザ(ONNX Runtime Web) | 量子化を考えた学習・蒸留は要る |
| 評価の方法 | mask AP → 境界の正確さ(Boundary AP)・ドメイン違いのデータセット → オープンボキャブラリーの指標(LVIS の珍しいクラスの AP など) | 要らない |

### 進める順番

合成データで学習するには、(1) 合成画像に正解のマスクを自動で付けられること、(2) 学習するモデル(スクラッチ実装)と学習の仕組みがあること、の 2 つが要る。
(1) はこの計画全体で一番の不確かさなので、モデルを作る前に確かめる。(1) と (2) はお互いに依存しない。
正解ラベルの作り方は、まず ① 生成だけ を確かめ、② 疑似ラベル・③ 組み合わせ は ① の後に比較として行う。

| 順 | exp | 何をするか | 前提 | 何がわかれば次に進むか |
|---|---|---|---|---|
| 1 | exp00001 | 評価の基盤・公開モデルの参照点・画像の生成の速さ | - | 評価のセットと評価のコードが正しく動き(公開モデルで公式の値を再現できる)、目標になる公開モデルの精度・速度と、1 枚の画像の生成にかかる時間がわかる |
| 2 | **exp00201** | **① 生成だけ で正解マスクを作る方法(①-a・①-c)の試作と、その質の確認**(学習はしない) | exp00001 | 正解のマスクを作れる割合・速さと、規則の誤差の出方がわかり、exp00202 で学習に使う設定を決められる |
| 3 | **exp00002** | 画像の判定モデル(decision model)での検品の仕組みの確かめ: (1) 生成した単一の物体が指定したクラスか、(2) 背景に学習するクラスの物体が入っていないか。答えのわかる問題で精度・較正・速さを測る | exp00201 | exp00201 で、1 段目の単一の物体の生成で頼んだクラスではない物体(20 クラスのどれでもない「何か」)が描かれること、2 段目の背景の inpainting で背景に学習するクラスの物体が描かれることがわかったため。③ の検品に使うモデルと設定が決まる |
| 4 | exp00101 | スクラッチのモデルの方式の一次比較(COCO の実データで学習) | exp00001 | 学習の仕組みができ、フェーズ B で固定するモデルが決まる。学習の速さから、フェーズ B の枚数・学習の長さを決められる |
| 5 | exp00101〜00107(フェーズ C) | 実データ(8 クラス・2,000 枚)だけで、モデルと学習の仕方を詰めて精度を上げる(下の「計画の見直し」) | 4 | 方式・データ拡張・backbone・学習の仕方の最良の組み合わせが決まり、公開モデルに近い精度になる |
| 6 | exp00202〜00205 | ① 生成だけ の方法で作ったデータで、5 で決めたモデルを学習し、実画像のベンチマークで比べる | 2・5 | ① だけでどこまで届くかがわかる |
| 7 | exp00206〜 | ② 疑似ラベル・③ 組み合わせ(exp00002 の検品を使う)との比較、要因の分析。以降、フェーズ D〜F | 3・6 | 各 exp の表のとおり |

2 と 3 はお互いに独立なので、GPU・メモリがあふれない範囲で並行して進めてよい(遅延を測るものは同時に動かさない)。

### 計画の見直し(exp00101 の最初の結果を受けて)

最初の計画では、exp00101 で方式を一度比べたら、合成データ(フェーズ B)に進み、フェーズ C(モデルの構成)はフェーズ B と交互に
進めるつもりだった。exp00101 の最初の 2 本(Mask2Former 系と RF-DETR-Seg。どちらも backbone は ResNet-50、20 クラス・
coco_train_10pct の 9,528 枚・50 エポック)を回した結果、次の 2 つがわかり、順番とデータの設計を見直した。

- 精度が低すぎた: 自前の Mask2Former 系の mask AP は coco_val_dev で 3.6(公開の RF-DETR-Seg nano は 44.0)。この精度のモデルで
  合成データを比べても、合成データの良し悪しが精度の差として見えない。モデルと学習の仕方を先に詰める必要がある
- 1 回の学習が長すぎた: 20 クラス・9,528 枚で 1 本 2〜3 時間かかり、比較の実験を何十回も回せない

そこで、

1. **フェーズ C(001xx)を先に、実データだけで進める。** 方式・データ拡張・backbone・学習の仕方を詰めて精度を上げてから、そのモデルで
   フェーズ B(合成データ)の比較に入る。exp00202 の合成データ(20 クラス)の生成は、途中まで作った分を残して止めておく
2. **比較の実験の基本のデータを、8 クラス・学習 2,000 枚にする**(「比較の実験の基本: 8 クラス・学習 2,000 枚」の節。1 本 30〜40 分の見込み)。
   学習データの量の影響は、データの量だけを変える比較の実験(exp00107)で見る
3. **データ拡張を独立した比較の実験にする**(exp00106)。exp00101 の基準は、公式の長い学習向けの LSJ(0.1〜2.0 倍)をそのまま
   使っており、短い学習には強すぎる可能性がある

公式の RF-DETR-Seg・公式の Mask2Former と自作の Mask2Former 系の違いは、exp00101 の README の「方式ごとの対応と違い(公式・自作)」の表に
すべて並べた。同じデータ・クラス・入力・エポック数で、backbone を同じ ResNet-50 にした公式の RF-DETR-Seg は 50 エポックで mask AP 28.8、
自作は 3.6 で、フェーズ C の最初は、この表の違いを 1 つずつ切り分けて自作の精度を公式に近づけることから始める。

exp00101 の最初の 2 本の結果(20 クラス・10%)は、そのまま残す。フェーズ C の進める順番(案): exp00101 の基準を 8 クラス・2,000 枚で
取り直す → exp00106 データ拡張 → exp00102 論文の実装との差 → exp00104 backbone → exp00103 最新の手法 → exp00105 学習の仕方の締め →
exp00107 データの量。1 本ごとの差が小さい比較では、乱数の種を変えて 2〜3 回回し、ばらつきより大きい差かを確かめる。

### フェーズ C: モデルの構成の比較

学習データは、COCO train の 8 クラス・2,000 枚(`coco_train_cls8_2k`)を基本にし、val は `coco_val_dev_cls8`(最良の重みを選ぶ)、test(最終の精度)は `coco_val_test_cls8`・`voc_val_cls8`。
フェーズ B より先に進める(「計画の見直し」の節)。フェーズ B の最良の合成データでの比較は、フェーズ B の後で必要なものだけ行う。

| exp | 基準 | 変えるもの | 狙い |
|---|---|---|---|
| exp00102 | 00101 の自作の方式 | 公式(論文)の実装との差を埋める。洗い出した差は exp00102 の README(Mask2Former 系の FPN の pixel decoder の実装(論文では FPN でも 41.5 と学習できる)・学習率の変化・初期値、YOLO26-seg 系の最適化・1 回の更新あたりの枚数・損失の重みなど)。多重解像度の deformable な pixel decoder と点を選ぶマスクの損失は exp00101 で済み | 一次比較の差が、方式の差か実装の簡略化の差かを切り分ける |
| exp00103 | 00102 | 最新の手法の比較: 着手時に最新の手法を調べ直し、有望なものをスクラッチ実装して比べる(2026-11 時点の候補: EoMT(ViT だけで完結)、RF-DETR-Seg・ECInsSeg 系(DETR 系の検出 + 軽いマスクのヘッド)、GTR)。古典の Mask R-CNN は比較の参考として 1 本だけ並べる | 最新の手法の良し悪しを、同じデータ・同じ学習の長さで確かめる |

## 正解ラベルの作り方の分類

学習データの正解のマスクを、**どこから来るか**で 3 つに分ける。分類が違うものを 1 つの exp で混ぜない。

| 分類 | 正解のマスクの出どころ | 正解に入る誤差 | 例 |
|---|---|---|---|
| **① 生成だけ** | 生成・合成の手順そのもの。学習済みの認識モデル(SAM 3 など)はラベルに一切触れない | 生成モデルと、決まった規則(色の閾値など)の誤差だけ | 下の ①-a〜①-f |
| **② 疑似ラベル** | 実画像に、学習済みの認識モデルが付けたもの | 認識モデルの誤り | ネット上のラベルのない画像 + SAM 3。COCO の画像 + SAM 3 |
| **③ 組み合わせ** | 生成した画像に認識モデルでラベルを付ける、または ① のマスクを認識モデル・判定モデルで直す・足切りする | 両方 | 生成したシーン + SAM 3。① の画像の判定モデルでの検品 |

**① 生成だけ の中の方法**

| 方法 | 正解のマスクの作り方 | 正解に入る誤差 |
|---|---|---|
| ①-a 色で抜いて合成 | 物体を無地の背景で 1 つずつ生成 → 背景の色との差で物体の画素を決める(決まった規則)→ 大きさ・位置・重なりを変えて合成し、貼った形を正解にする | 規則の誤差(輪郭の数画素・影・背景に近い色の物体)。合成した画像に対しては、貼ったマスクがそのまま正解 |
| ①-b 透明(RGBA)で生成 | 生成モデルが透明度(アルファ)も一緒に出し、それを正解にする | 生成モデルの透明度の誤差。候補: FLUX.2 Klein Alpha(非商用、LoRA は 9B 用)、Qwen-Image-Layered(57.7GB)。使えるかは未確認 |
| ①-c 背景を inpainting | ①-a の合成画像の、物体以外の部分を inpainting で描き直し、最後に物体の画素を元に戻す | ①-a と同じ(物体は変えない)。背景に余計な物体が描かれると、ラベルのない物体になる(① では取り除かず、その割合だけを測る) |
| ①-d 生成の途中の注意の地図 | 生成の途中の、文章の言葉ごとの注意(cross-attention)の地図をマスクにする(DiffuMask・MosaicFusion 系) | 粗い(解像度が低い) |
| ①-e マスクを先に決めて描く | 配置したマスクの部分だけを inpainting で描き、入力したマスクを正解にする。密集・重なり・小さい物体を意図して作れる | 生成モデルがマスクを埋めきらない・はみ出す分 |
| ①-f 3D レンダリング | 3D の物体を置いて描画し、物体の領域を正解にする | なし(見た目の差が課題) |

**認識モデルの使い分け**: ① の exp では、SAM 3 などの認識モデルを、正解のマスクを作ることにも、捨てるかどうかを決めることにも使わない。
① の質は、モデルを使わずに測れる値(物体のまとまりの数・画像の端で切れていないか・面積)と見本の画像で確かめ、最終的には学習して実画像のベンチマークで測った精度で判断する。
② ③ は、① の結果が出た後に、比較として行う。

### 精度の指標

計算は faster-coco-eval(COCO 公式の評価の pycocotools と同じ計算を C++ で速くしたもの)で行う
(実装は [lib_common/evaluate.py](lib_common/evaluate.py))。値は 0〜1 で保存し、表には論文と同じく 100 倍して書く。

優先度: **A** = 主な指標(全 exp の「結果のまとめ」の表に必ず載せる)、**B** = 各 exp の README に載せ、差の理由を見るのに使う、
**C** = 必要なときだけ見る(結果の JSON には全部保存する)。

**AP 系の指標**(IoU を閾値で区切って当たり・外れを数え、その数から計算する)

| 優先度 | 指標 | 定義 | 何を見るか |
|---|---|---|---|
| **A** | **mask AP** | IoU の閾値を 0.50〜0.95 で 0.05 刻みにした 10 個それぞれの AP を平均し、さらにクラスで平均したもの。IoU はマスクどうしで計算する | 見つけられたかと、形の正確さの両方。論文の表と比べる値 |
| B | AP50 / AP75 | IoU の閾値 0.50 / 0.75 だけでの AP | AP50 は「だいたいの位置で見つけられたか」、AP75 は「形がかなり正確か」 |
| B | APs / APm / APl | 正解の面積が 32² 画素未満 / 32²〜96² / 96² 以上の物体だけで計算した mask AP | 小さい物体・大きい物体の得意・不得意 |
| B | Boundary AP | IoU を「マスクの IoU」と「輪郭の帯の IoU」の小さい方にして計算した AP(Boundary IoU、Cheng ら CVPR 2021) | 輪郭の正確さ。普通の mask AP は大きい物体の輪郭のずれに甘いので、それを補う |
| B | クラスごとの mask AP | 上の mask AP を、クラスで平均する前の値 | 合成データで得意・不得意なクラス |
| C | AR100 | 1 画像・1 クラスあたりスコアの上位 100 個まで出したときの再現率を、10 個の IoU の閾値とクラスで平均したもの | 取りこぼしの少なさ |
| C | box AP | IoU をマスクではなく枠どうしで計算した AP。枠は、予測が出せばそれを、出さなければマスクを囲む枠を使う | 検出としての性能(検出の論文・モデルとの比較) |

**画素単位の指標**(マスクの IoU そのものを平均する。実装は [lib_common/pixel_metrics.py](lib_common/pixel_metrics.py))

| 優先度 | 指標 | 定義 | 何を見るか | スコアの閾値 |
|---|---|---|---|---|
| **A** | **SQ** | 予測と正解を 1 対 1 で対応させ、IoU > 0.5 で対応した組の IoU の平均(クラスごとに計算してクラスで平均) | **見つけた物体のマスクの形の正確さ**。0.5〜1 の連続値で、AP では見えない形の差が出る | 要る |
| B | PQ / RQ | RQ = TP ÷ (TP + ½FP + ½FN)(見つけ方の良さ。F1 と同じ)、PQ = SQ × RQ(Panoptic Quality の物体の部分。Kirillov ら CVPR 2019) | 1 つに決めた予測の集まりとしての良さ(実際に使うときに近い) | 要る |
| B | 正解ごとの最良の IoU の平均 | 正解の物体ごとに、同じクラスの予測との IoU の最大値を取り、全部の正解で平均する(予測がなければ 0) | 「どこかに良いマスクの候補を出せているか」。スコアの付け方に左右されない | 要らない |
| C | semantic mIoU | 予測を画素ごとのクラスの地図にし、データセット全体でクラスごとの「重なる画素 ÷ 和の画素」を計算してクラスで平均 | 物体を 1 つずつ分けられたかは問わない、画素単位のクラス分けの正確さ | 要る |
| C | 前景の IoU | 上と同じ地図で、クラスを問わず「物体か背景か」だけの IoU | 物体の領域そのものを取れているか | 要る |

**計算の手順**(AP 系。どの AP も同じで、違うのは IoU の計算の仕方だけ)

1. **IoU**: マスクの IoU は「正解と予測の両方に入る画素の数 ÷ どちらかに入る画素の数」。枠の IoU は同じことを枠の面積で計算する
2. **対応付け**(画像 × クラスごと): 予測をスコアの高い順に並べ(上位 100 個まで)、上から順に、まだ対応していない正解のうち IoU が閾値以上で最大のものと対応させる。
   対応できた予測は正解(TP)、できなかった予測は誤検出(FP)。1 つの正解に対応できる予測は 1 つだけなので、同じ物体への 2 つ目以降の予測は誤検出になる
3. **群衆の領域**(`iscrowd=1`。人混みなど 1 つずつ分けられない所にまとめて付けたラベル): 群衆の領域と対応した予測は、TP にも FP にも数えない。
   群衆の領域との IoU は「重なる画素の数 ÷ 予測の画素の数」で計算し、複数の予測が対応できる。群衆の領域は取りこぼしにも数えない
4. **AP**(クラス × IoU の閾値ごと): 全画像の予測をスコアの高い順に並べ、上から順に適合率(TP ÷ ここまでの予測の数)と再現率(TP ÷ 正解の数)を計算する。
   適合率を「その再現率以上での適合率の最大値」に置き換えてから、再現率 0, 0.01, …, 1.00 の 101 点での適合率を平均したものが AP(届かない再現率の点は 0)
5. **平均**: 10 個の IoU の閾値で平均したあと、クラスで平均する(正解が 1 つもないクラスは除く)。物体の数が多いクラスも少ないクラスも同じ重みになる
6. **面積の区分**(APs・APm・APl): 区分の外の正解は無視し、区分の外の予測のうち正解と対応しなかったものも無視する

**輪郭の帯**(Boundary AP): マスクのうち、輪郭から d 画素以内にある画素(マスクから、3×3 の縮小を d 回かけたマスクを引いたもの)。
d = round(0.02 × 画像の対角線の長さ)で、640×480 の画像なら 16 画素。画像の端で切れている所も輪郭として扱う。
輪郭の帯の IoU は、正解の帯と予測の帯で、1. と同じように計算する(群衆の領域はマスクの IoU だけを使う)。

**計算の手順**(画素単位の指標)

1. **スコアの閾値**(SQ・PQ・RQ・semantic mIoU・前景の IoU で使う): モデルによってスコアの出方が違うので、固定の値にはしない。
   dev のセット(`coco_val_dev`)で、0.05〜0.95(0.05 刻み)のうち PQ が最大になる値を選び、test・ほかのセットにはその値をそのまま使う
2. **1 対 1 の対応**(SQ・PQ・RQ): 画像 × クラスごとに、閾値以上の予測(上位 100 個まで)と正解のマスクの IoU を全部計算し、
   IoU の合計が最大になる 1 対 1 の組み合わせ(ハンガリアン法)を選ぶ。そのうち IoU > 0.5 の組が TP、対応しなかった正解が FN、
   対応しなかった予測が FP。ただし、画素の半分以上が同じクラスの群衆の領域に入っている予測は FP に数えない(COCO の panoptic の評価と同じ)
3. **SQ・RQ・PQ**: クラスごとに SQ = TP の組の IoU の合計 ÷ TP、RQ = TP ÷ (TP + ½FP + ½FN)、PQ = SQ × RQ を計算し、正解のあるクラスで平均する
4. **正解ごとの最良の IoU**: 閾値をかけずに上位 100 個までの予測を使う。群衆の領域は正解に含めない
5. **画素ごとのクラスの地図**(semantic mIoU・前景の IoU): 予測は、閾値以上のものをスコアの低い順に塗る(重なった所はスコアの高い予測のクラス)。
   正解は物体のマスクを塗る。群衆の領域の画素と、正解で別のクラスの物体が重なる画素(COCO では物体の画素の約 1.4%)は、クラスが決まらないので計算に入れない。
   画素の数はデータセット全体で足し合わせてから IoU を計算する(画像ごとの IoU の平均ではない)

**値の目安**(mask AP)

- COCO の mask AP は、IoU 0.85〜0.95 のような厳しい閾値がほとんど当たりにならないため、見た目でかなり良い予測でも 0.5 前後になる
  (exp00001 で、SAM 3・RF-DETR-Seg 2xlarge は AP50 が 0.77〜0.79 でも、IoU 0.95 では 0.03〜0.05)。正解のマスクも多角形でなぞったもので輪郭が数画素ずれるので、
  正解のマスクを 2 画素縮めただけで mask AP は 1.000 → 0.414 になる(exp00001 の評価の仕組みの確認)
- 論文の最上位のモデルでも COCO(80 クラス)の mask AP は 0.55 前後(Mask DINO 0.545)。モデルどうしの比較では 0.01 の差でも意味がある
- 見た目の「見つけられたか」に近いのは AP50、見つけた物体の形の正確さは SQ(exp00001 の公開モデルで 0.81〜0.84)

**評価のときの決まり**

- AP は、スコアの低い予測をたくさん出しても下がりにくい(誤検出はスコアの順位が下の方に並ぶだけなので)。
  そのため評価では、スコアの閾値をかけずに、1 画像・1 クラスあたり上位 100 個までを出す。閾値の要る指標は、上の 1. の閾値を使う
- 予測のマスクは、元の画像の大きさに戻してから評価する

### 速度の指標

| 優先度 | 指標 | 定義 |
|---|---|---|
| **A** | **遅延(前後の処理込み)** | 読み込んだ画像の配列を入れてから、元の画像の大きさのマスク・クラス・スコアが出るまでの時間(前処理・推論・後処理)。実際に使うときの速さ |
| B | 遅延(モデルだけ) | 前処理の済んだテンソルを入れてから、モデルの出力(後処理の前)が出るまでの時間。モデルの構成どうしの比較用 |
| B | パラメータ数・FLOPs | FLOPs は評価の入力解像度で 1 枚あたり |
| C | スループット | 1 秒あたりに処理できる画像の数(batch を大きくしたときも別に記録する) |
| C | GPU メモリ | 推論中の最大の使用量 |

- 遅延の測り方: batch 1、入力の解像度は固定、最初の何回か(warmup)を捨ててから複数回測り、中央値と p90(遅い方から 10% の所)を出す。
  GPU は処理の終わりを待ってから(`torch.cuda.synchronize`)時刻を取る

- **精度は、実際に動かす形式(TensorRT の INT8 など)で測る**(速さは量子化したモデル、精度は元のモデル、という組み合わせにしない)
- 計測する機器: この PC(RTX 5090 / CPU / ブラウザ)。他の機器は後で足す

### 答えが漏れないための決まり

- 学習の初期値に、COCO などで学習済みの検出・セグメンテーションの重みは使わない(backbone の事前学習の重みは「外部モデル」の軸として使う)
- 合成データの文章を作るときに、COCO のラベルの統計(クラスの組み合わせなど)を使わない。物の組み合わせは LLM に考えさせる
- SAM 3 の学習データに評価の画像が入っている可能性は否定できない。そのため、SAM 3 をそのまま評価データで動かした精度も基準として並べる
- LVIS は画像が COCO と重なるので、COCO train を学習に使ったモデルを LVIS で評価するときは、重なる画像を除く(重なりの確認は使う段階で行う)

## 画像の判定モデル(decision model)の使い方

decision model は、「状態(文章)+ 画像」と質問・選択肢を入れると、文章を生成せずに**選択肢ごとの確率**を 1 回の計算で返すモデル
(TypeSafe AI の Jev が始まりで、2026 年に公開の重みのモデルが多数出ている)。答えが必ず選択肢のどれかになり、確率が当たりやすさに合うよう較正されていて、
1 回が数十〜数百 ms と速い。大量の画像・物体に「はい / いいえ」やクラスを自動で付ける仕事に向くので、次の所で使う。

| 使いどころ | 中身 | exp |
|---|---|---|
| 合成データの検品(③ 組み合わせ) | ① で作った画像・物体の切り出しごとに「これは {クラス} か」「物体が途中で切れていないか」「不自然でないか」を確率で判定する。確率の閾値で捨てる場合と、確率を学習の重みに使う場合(捨てずに重みを下げる)を比べる | exp00208・00209 |
| 疑似ラベルの確認(② ③) | SAM 3 の疑似ラベルのマスクを切り出し、「20 クラスのどれか / どれでもない」を選ばせてクラスの取り違えを直す。SAM 3 自身のスコアでの足切りと比べる | exp00206・00207・00208 |
| 誤りの原因の分類 | 評価で外れた予測・取りこぼした正解を「小さい / 隠れている / 画像の端で切れている / 珍しい向き / 暗い / 正解のラベルの誤り」から選ばせ、モデルごとの誤りの内訳を出す。苦手な条件を重点的に生成する手がかりにする | 各 exp の分析 |
| 2 段のオープンボキャブラリー | クラスを問わずにマスクの候補を出し、候補ごとにクラスを選ばせる(較正された確率をそのまま AP のスコアに使える) | exp00403 |
| 動画 | 追跡した物体の列を見せて、クラスや同じ物体かどうかを判定させる(動画を入力できるモデルで) | 005xx |

**モデルの候補**(2026-11 時点。画像の判定のベンチマーク ImageJevBench v0.3.0(2,441 問)での公開の重みのモデルの上位。値は能力の総合点 / 較正の点 / 遅延の中央値)

| モデル | 元のモデル | ImageJevBench | 備考 |
|---|---|---|---|
| H2O-Lightning-31B | Gemma 4 31B IT | 80.9 / 86.1 / 0.59 秒 | 公開の重みで能力が最上位。32GB の GPU には量子化しないと載らない |
| Imajev-4B | Qwen3.5-4B(LoRA) | 68.0 / 86.1 / 0.37 秒 | 小さいモデルで較正が最も良い |
| H2O-Lightning-4B v1.4.1 | Qwen3.5-4B | 66.2 / 76.9 / 0.32 秒 | 総合の順位(速さ・費用込み)は公開の重みで最上位 |

ImageJevBench の問題は、画面の写真・文書・グラフ・数え上げなどが中心で、物体の写真のクラス分けとは傾向が違う。そのため、
**正式に使う前に、このタスクの問題で選び直す**(exp00002): COCO の正解の物体の切り出し(クラスがわかっている)と、SAM 3 の誤った予測の切り出しで
「20 クラスのどれか / どれでもない」を答えさせ、正解率・較正(ECE)・速さを比べる。CLIP・SigLIP 2 で選択肢の文章との近さを確率にする方法と、
普通の VLM に答えさせる方法も、同じ問題で並べる。

注意: 選択肢の形で答えるモデルは、選択肢の意味より名前に引っ張られて選ぶことがあると指摘されている(arXiv 2609.26758)。選択肢は短く、意味がはっきりした名前にする。
