# exp00302: 量子化

## 目的

exp00301 で書き出した fp32 の ONNX を INT8 に量子化して、ファイルを 1/4 程度に小さくし(GitHub の 1 ファイルの上限 100MB に収め、
GitHub Pages のブラウザのデモ(exp00304)に載せる)、精度がどれだけ落ちるかを測る。インスタンスセグメンテーションの README の計画どおり、
量子化の調整には**合成画像だけを使い**、実データなしで量子化できるかも見る(比べるため、学習データの実画像で調整した版も作る)。

## 量子化のやり方

2 つの作り方を試す。どちらも、量子化するのは exp00301 の `--webgpu` で書き出した fp32 の ONNX(ブラウザの WebGPU で動く形。
計算は元と同じ)。

| 作り方 | 8 ビットにするもの | 計算 | 調整の画像 |
|---|---|---|---|
| 静的な量子化(`quantize.py`) | 重みと、計算の途中の値 | 8 ビットの整数で計算する | 要る(途中の値の範囲を決める) |
| 重みだけ(`quantize_weights.py`) | ファイルの中の重みだけ | INT8 の重みを fp32 に戻して(DequantizeLinear)、fp32 で計算する。戻すのを読み込むときに 1 回だけにするには、ONNX Runtime の設定が要る(下の「重みを戻す処理」) | 要らない |

### 重みだけ(`quantize_weights.py`)

- 畳み込み・行列の掛け算の重み(2 次元以上で、ある程度大きいもの)を、出力のチャンネルごとの対称な INT8 にする
  (scale = そのチャンネルの絶対値の最大 / 127)。使うところで DequantizeLinear で fp32 に戻す
- **重みを戻す処理**: ONNX Runtime は既定では、量子化したモデルの最適化(QDQ の組を INT8 の演算にまとめるなど)のために、
  DequantizeLinear を定数にまとめずに残す。そのため、重みだけ INT8 のモデルでも、推論のたびに重みを INT8 から fp32 に戻す計算が走る
  (サイトの GTR 系で、最適化の後も 136 個が残り、53 個の行列の掛け算は INT8 の重みのまま計算する MatMulNBits に置き換わっていた)。
  セッションの設定 `session.disable_quant_qdq = 1` を入れると、DequantizeLinear は読み込むときに 1 回だけ計算されて定数になる(最適化の後
  0 個)。精度は同じ(test の先頭 300 枚で mask AP 35.84 と 35.88。fp32 のファイルは 35.72)で、ネイティブの CPU で 4 スレッド −17%・
  8 スレッド −7%(同じ時に交互に測った値)。ブラウザ(exp00304)の Worker にもこの設定を入れた(ブラウザでの効き方は、WebGPU で −4%、
WASM で −1〜2% とネイティブより小さい。exp00304 の README の問題 10)
- ONNX Runtime の量子化の機能にはこの形がないので、onnx のグラフを直接書き換える

### 静的な量子化(`quantize.py`)

- ONNX Runtime の静的な量子化(`quantize_static`)。形式は QDQ(量子化と戻しの組を、量子化する演算の前後に入れる形。ONNX Runtime の
  CPU・CUDA・Web のどれでも読める)
- 重みは出力のチャンネルごとの INT8、途中の値も INT8(MinMax: 調整の画像を通したときの最小・最大で範囲を決める)
- 量子化するのは ONNX Runtime が量子化に対応する演算(畳み込み・行列の掛け算など)だけ。GridSample などは fp32 のまま
- GTR 系は、Gather・GatherElements も fp32 のまま残す(`--keep-fp32-ops Gather,GatherElements`。理由は下の「GTR 系の INT8 が
  壊れた原因」)
- 量子化の前に `quant_pre_process`(形の推定とグラフの整理)を通す
- 調整の画像(120 枚、前処理は評価と同じ `transforms.eval_transforms`):
  - synthetic: exp00201 で生成した合成画像(`runs/q2` の paste・inpaint_full_empty・inpaint_full_noclass、40 場面 × 3)
  - real: 学習データ(`coco_train_cls8_2k`)の先頭の 120 枚(評価のデータは使わない)
- コード: `quantize.py`(量子化)、`eval_onnx.py`(評価。exp00301 の `eval_onnx.py` を、出力の場所だけ変えて動かす)

## 精度の測り方

- 学習のときの最後の評価と同じ手順(dev で PQ の閾値を選び、test・voc で測る)。精度は test(`coco_val_test_cls8`・`voc_val_cls8`)
- 実行は ONNX Runtime の CUDA(TF32 なし)。CUDA では QDQ の INT8 の値を戻してから fp32 で計算するので、量子化の誤差はそのまま入り、
  ブラウザの WebGPU で動かすときに近い。CPU は INT8 のまま計算する専用の処理になるので計算の仕方が違い、遅いので測っていない
- 比べる相手: exp00301 の fp32 の ONNX(同じ ONNX Runtime の CUDA・TF32 なし)

## 結果

### 量子化したファイル

| 候補 | fp32(exp00301) | 静的な量子化 | 重みだけ |
|---|---|---|---|
| 自作の GTR 系 + hybrid encoder | 146MB(グラフ 2.5MB + 重み 143MB) | 37.8MB | 42.0MB |
| 自作の YOLO26-seg 系 | 180MB(グラフ 1.2MB + 重み 179MB) | 45.7MB | 46.2MB |

INT8 はどれも 1 つのファイルで、GitHub の 1 ファイルの上限(100MB)に収まる。静的な量子化は、調整の画像(synthetic・real)によらず
大きさは同じ。

ブラウザのデモ(exp00304)では、WebGPU で GPU だけで動く重みだけの INT8(`quantize_weights.py`)を使う。理由は exp00304 の README。

### GTR 系の INT8 が壊れた原因(静的な量子化)

既定の設定(量子化に対応する演算の全部)で量子化した GTR 系は、どの画像でもスコアがほぼ 0 になった(ブラウザでも Python の
ONNX Runtime でも同じ)。量子化する演算の種類を変えて、test の先頭の 20 枚の「画像ごとの最高スコア」を fp32 と比べた
(診断のため調整の画像は実画像 16 枚)。

| 量子化した演算 | fp32 との最高スコアの差の平均 |
|---|---|
| 全部(既定) | 0.470(スコアがほぼ 0 になる) |
| 畳み込みだけ | 0.045 |
| 行列の掛け算だけ | 0.009 |
| 全部から Where を外す | 0.471 |
| 全部から LayerNormalization を外す | 0.471 |
| 全部から TopK を外す | 0.471 |
| 全部から Gather・GatherElements を外す | 0.038 |

(fp32 の最高スコアは 0.1〜0.9 程度)

Gather・GatherElements を量子化すると壊れる。GTR 系はこれで、encoder の出力から上位のクエリの特徴と参照の枠を選び出している。
そのため GTR 系はこの 2 つを fp32 のまま残す。選び出す値のどれが量子化で壊れるのか(範囲の広い値が混ざっているのかなど)は、
まだ確かめていない。

### 精度

値は %。比べる相手は exp00301 の fp32 の ONNX(ONNX Runtime の CUDA・TF32 なし)。INT8 は `--webgpu` で書き出した ONNX から作ったもの
(計算は fp32 の ONNX と同じ。出力の差の最大 4e-5: exp00304 の README)。

| 候補 | 形式 | test mask AP | voc mask AP | test box AP | voc box AP | test PQ | voc PQ |
|---|---|---|---|---|---|---|---|
| 自作の GTR 系 + hybrid encoder | fp32 | 31.83 | 38.35 | 34.42 | 48.82 | 41.45 | 48.05 |
| | 重みだけ INT8 | 31.91 | 37.83 | 34.46 | 48.11 | 41.26 | 47.55 |
| 自作の YOLO26-seg 系 | fp32 | 30.71 | 35.77 | 33.73 | 45.24 | 42.59 | 47.66 |
| | 重みだけ INT8 | 30.73 | 35.43 | 33.61 | 44.90 | 42.18 | 46.50 |

- 重みだけの INT8 にしても、test の mask AP は変わらない(+0.1・+0.0 ポイント)。voc は 0.3〜0.5 ポイント下がる
- 静的な量子化の精度(と、合成画像・実画像の調整の比べ)は測っていない。サイトで重みだけの INT8 を使うことにしたので、評価を取りやめた。
  GTR 系の静的な量子化は、既定の設定では壊れる(上の「GTR 系の INT8 が壊れた原因」)
