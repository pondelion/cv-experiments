# exp00102: 自作の実装と公式(論文)との差を埋める

## 目的

exp00101 の自作の方式と、公式のコード・論文との違いのうち、**公式の側に寄せると精度が上がりそうなもの**を洗い出し、1 つずつ
確かめる。exp00101 の方式どうしの差が「方式の差」なのか「自作の実装の簡略化・違いの差」なのかを切り分けるのが狙い。

ほかの exp で扱うものは、ここでは扱わない:

| 違い | 扱う exp |
|---|---|
| データ拡張(公式の Mosaic・Copy-Paste など) | exp00106 |
| backbone(論文の専用の backbone、ViT・DINOv3 など) | exp00104 |
| 学習の長さ・入力の大きさ(公式の 1024・640 など)・複数の解像度での学習 | exp00105 |

## 基準

exp00101 の統一の条件(train `coco_train_cls8_2k`、val `coco_val_dev_cls8` の先頭 500 枚で最良の重みを選ぶ、test
`coco_val_test_cls8`・`voc_val_cls8`、データ拡張 `lsj`、100 エポック、batch 16、入力 512)の自作の結果(mask AP):

| 方式 | test | voc | 比べる相手(公式) |
|---|---|---|---|
| 自作: YOLO26-seg 系 | 30.7 | 35.7 | 公式の YOLO26-seg: test 30.5・voc 32.8 |
| 自作: GTR 系 | 30.3 | 36.1 | (公式は学習していない) |
| 自作: RF-DETR-Seg 系 | 27.3 | 32.6 | 公式の RF-DETR-Seg: test 26.3・voc 31.9 |
| 自作: Mask2Former 系(msdeform) | 26.8 | 34.3 | (公式は学習していない) |
| 自作: Mask2Former 系(FPN) | 6.0 | 7.2 | 同上 |

## exp00101 で済んだもの

| 方式 | 違い | 結果 |
|---|---|---|
| Mask2Former 系 | pixel decoder を簡略版の FPN から公式と同じ多重解像度の deformable な注意の encoder(msdeform)にした | test 6.0 → 26.8、voc 7.2 → 34.3 |
| Mask2Former 系 | 点を選んで計算するマスクの損失(1 マスクあたり 12,544 点。不確かな点を多めに選ぶ) | 初めから公式と同じ |
| Mask2Former 系 | transformer decoder・損失・割り当てを公式のコードと照らし合わせた | 同じ(違いは注意と FFN の重みの初期値だけ。下の M3) |
| RF-DETR-Seg 系 | 公式とそろうかの確認 | そろった(test 27.3 と 26.3) |
| GTR 系 | 損失を公式のコードと同じ入力で比べた | 一致した |

## 洗い出した差

「確かめたこと」は、論文・公式のコード・exp00101 の README の対応表で実際に確かめた事実。「見込み」はまだ確かめていない。

### Mask2Former 系

| 番号 | 違い | 公式・論文 | 自作 | 確かめたこと | 見込み |
|---|---|---|---|---|---|
| M1 | **FPN の pixel decoder の実装** | 論文の表 4(e)(R50、COCO の instance AP): FPN 41.5、MSDeformAttn 43.7。**FPN でも 2.2 しか下がらない** | FPN 6.0、msdeform 26.8(test)。**20 以上下がる** | 論文の値。自作の FPN(`lib_common/models/mask2former.py` の `PixelDecoder`)は、横からの 1×1 の畳み込みに正規化がなく、上の段から渡すのは出力の 3×3 の畳み込みの前の値 | 論文では FPN でも学習できているので、自作の FPN か、FPN と組み合わせたときの何か(decoder に渡す段・初期値など)に、公式と違う所がある。公式の FPN(MaskFormer の `BasePixelDecoder`)と 1 行ずつ照らし合わせて違いを全部出し、直して学習する。UNet も同じく学習できなかった(test 5.1)ので、原因が同じかも確かめる |
| M2 | 学習率の変化 | 88.9%・96.3% の時点で 10 倍ずつ下げる(warmup 10 回) | warmup 500 回、poly(0.9 乗)で 0 まで | 公式の設定ファイル | 効果は小さいと見るが、確かめるのは安い |
| M3 | 注意と FFN の重みの初期値 | xavier | PyTorch の既定 | 公式のコード | 効果は小さいと見る。M1 で FPN が直らないときの候補 |
| M4 | backbone の BatchNorm | 固定(FrozenBN) | 学習する(ほかの自作の方式も公式の RF-DETR-Seg も学習する) | 公式の設定 | 方式どうしの条件をそろえるため、今は変えない。M1〜M3 の後に必要なら |

### YOLO26-seg 系

自作は論文だけから作った(公式のコードは AGPL)。精度はすでに公式と同じかそれより高い(test 30.7 と 30.5、voc 35.7 と 32.8)ので、
公式に寄せても上がるとは限らない。

| 番号 | 違い | 公式・論文 | 自作 | 確かめたこと | 見込み |
|---|---|---|---|---|---|
| Y1 | 最適化の手法 | 論文は MuSGD(Muon + SGD)。公式のコードは、更新の回数が 1 万回より少ないと AdamW(学習率 = 0.01 × 5 / (4 + クラスの数)。8 クラスで 8.33e-4)を選ぶ(今の条件はこちら) | SGD 0.01(論文に混ぜ方の値がなかったため) | 公式のコード(`engine/trainer.py` の `build_optimizer`)と学習の記録 | 公式と同じ AdamW にするか、MuSGD を論文どおりに入れるか。どちらも 1 本ずつ |
| Y2 | 1 回の更新あたりの枚数 | 64 枚(16 枚 × 勾配の累積 4 回。weight decay も枚数に合わせて変える) | 16 枚 | 公式のコード(`nbs=64`) | 更新の回数が 1/4 になる。Y1 と組み合わせて公式の設定として 1 本にまとめるのがよい |
| Y3 | 損失の重み | 公式の既定の設定は box 7.5・cls 0.5・dfl 1.5(学習の記録の設定の一覧) | 論文の付録の表の値(枠の CIoU 9.83・クラス 0.65・マスク 9.83 など) | 公式の既定の値だけ。YOLO26 で実際に使われる重みは、コードの中での掛け算を含めてまだ確かめていない | まず公式のコードで実際の値を確かめる |

公式のコードの値を参考にして自作を変えることは、exp00101 で決めた「論文だけから作る」の方針を変えることになる。Y1〜Y3 を
進めるかは、その方針を変えてよいかで決める。

### RF-DETR-Seg 系

公式とそろっている(test 27.3 と 26.3)ので、寄せても上がる見込みは小さい。記録として残す。

| 番号 | 違い | 公式 | 自作 | 見込み |
|---|---|---|---|---|
| R1 | 正解の枠 | 注釈の枠 | マスクを囲む枠 | 小さい |
| R2 | 計算の型 | 自動の混合精度(fp16) | bf16 | 小さい |

### GTR 系

| 番号 | 違い | 公式 | 自作 | 見込み |
|---|---|---|---|---|
| G1 | 計算の型 | fp32 | bf16 | 小さい。分布で表す枠(FDR)は細かい値を扱うので、fp32 で確かめる価値はある |
| G2 | backbone の後の特徴の作り方 | 1 つの ViT の 3 つの層を 2・1・0.5 倍にする | R50 の段を補間してつなぎ、C2f でまとめる | backbone と切り離せないので exp00104 で扱う |

## 進め方

1. **M1(FPN の実装の差)を最初に行う**。差が 20 以上と最も大きく、原因がわかれば UNet にも効く可能性がある。まず公式のコードと
   照らし合わせて違いを全部書き出し、直す前後を 100 エポックで比べる
2. M2・M3 を 1 本ずつ(基準は M1 の後の FPN、または msdeform)
3. Y1〜Y3 は、「論文だけから作る」の方針を変えてよいか決めてから
4. R1・R2・G1 は、上の結果を見て必要なら

どれも exp00101 の統一の条件で学習し、test・voc の mask AP で比べる。同じ条件での学習のやり直しのぶれは 1 前後なので、1 前後の差は
差とみなさない。1 本あたり 1〜2 時間。
