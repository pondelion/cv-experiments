# exp00001: 評価の基盤と、比較対象の基準

## 目的

以降のすべての exp で使う、評価のデータセット・評価の仕組み・推論速度の測り方を作る。
あわせて、公式の学習済みの公開モデル(RF-DETR-Seg・SAM 3)をそのまま評価し、スクラッチ実装と合成データの目標になる参照点を作る。

## 評価のセット

クラスは Pascal VOC の 20 クラス(COCO のクラス名にそろえ、ID は 1〜20 の通し番号。[lib_common/classes.py](../../../lib_common/classes.py))。
どのセットも共通の COCO 形式に変換して `datasets/sets/{セット名}.json` に置く([lib_common/datasets.py](../../../lib_common/datasets.py))。

| セット | 元のデータ | 画像 | 物体(群衆の領域) | 使い方 |
|---|---|---|---|---|
| `coco_val_dev` | COCO val2017 を seed 0 で並べ替えた前半 | 2,500 | 9,973(160) | 主な評価。手法選びに何度も使う |
| `coco_val_test` | 同じく後半 | 2,500 | 10,658(159) | 節目でだけ使う |
| `voc_val` | Pascal VOC 2012 val | 1,449 | 3,427(0) | 別の撮り方・ラベルの付け方での評価 |

- COCO のセットは、20 クラスの物体が写っていない画像も残す(そこに出した予測は誤検出として数える)
- VOC のマスクで、物体の輪郭に沿った数画素の帯(画素値 255 の「判定しない領域」)は、COCO 形式では表せないので、どの物体にも含めていない。
  そのため、輪郭まで正確な予測でも、VOC では IoU が少し下がる

実データでの基準に使う学習のセット(COCO train2017 のうち、20 クラスの物体が 1 つ以上ある画像):

| セット | 画像 | 物体(群衆の領域) |
|---|---|---|
| `coco_train` | 95,279 | 485,495(7,317) |
| `coco_train_10pct` | 9,528 | 48,225(736) |
| `coco_train_1pct` | 953 | 4,618(62) |

## 評価の仕組み

[segmentation/instance_segmentation/lib_common/evaluate.py](../lib_common/evaluate.py)。faster-coco-eval で、
mask AP(主な指標)・box AP・Boundary AP(輪郭の正確さに厳しい AP)と、クラスごとの mask AP を出す。
指標の定義と計算の手順は、[インスタンスセグメンテーションの README の「評価の設定」](../README.md#精度の指標)に書いた。

## 結果

### 公開モデルの精度・速度(20 クラス)

公式の学習済みの重みをそのまま動かした(`eval_sam3.py`・`eval_rfdetr.py`、まとめて `run_all.sh`)。
SQ・PQ などのスコアの閾値は、モデルごとに coco_val_dev で PQ が最大になる値(SAM 3 は 0.65、RF-DETR-Seg はどのサイズも 0.4)を選び、test・VOC にもその値を使った。
遅延は RTX 5090 で、1 枚あたりの前後の処理込みの中央値(下の「動かし方」を参照)。

| モデル | パラメータ | 入力 | 遅延(p90) | **mask AP** dev / test / VOC | **SQ** dev / test / VOC | AP50 | APs / APl | Boundary AP | box AP | PQ | 最良の IoU の平均 | semantic mIoU |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| SAM 3 | - | 1008 | 199.1ms(211.8) | 0.497 / 0.505 / **0.593** | 0.825 / 0.827 / **0.838** | 0.768 | **0.329** / 0.616 | 0.298 | 0.611 | 0.621 | 0.775 | 0.708 |
| RF-DETR-Seg nano | 33.6M | 312 | 8.3ms(11.0) | 0.440 / 0.445 / 0.557 | 0.814 / 0.814 / 0.822 | 0.689 | 0.144 / 0.663 | 0.243 | 0.542 | 0.569 | 0.660 | 0.712 |
| RF-DETR-Seg small | 33.7M | 384 | 7.7ms(9.6) | 0.466 / 0.474 / 0.564 | 0.820 / 0.821 / 0.824 | 0.728 | 0.176 / 0.670 | 0.271 | 0.570 | 0.593 | 0.696 | 0.714 |
| RF-DETR-Seg medium | 35.7M | 432 | 10.2ms(12.7) | 0.485 / 0.489 / 0.568 | 0.825 / 0.823 / 0.826 | 0.743 | 0.209 / 0.680 | 0.289 | 0.589 | 0.600 | 0.732 | 0.715 |
| RF-DETR-Seg large | 35.9M | 504 | 10.4ms(12.1) | 0.498 / 0.504 / 0.573 | 0.830 / 0.830 / 0.830 | 0.760 | 0.232 / 0.681 | 0.307 | 0.602 | 0.610 | 0.750 | 0.717 |

| RF-DETR-Seg 2xlarge | 38.6M | 768 | 18.6ms(21.4) | **0.533** / **0.531** / 0.577 | **0.837** / **0.836** / 0.828 | **0.789** | 0.320 / **0.688** | **0.336** | **0.629** | **0.634** | **0.785** | 0.717 |

(入力は、正方形に縮小・拡大したときの一辺の画素数。AP50 から右は coco_val_dev の値。SAM 3 のパラメータの数は、この exp では数えていない)

- **COCO では RF-DETR-Seg の大きいサイズが SAM 3 を上回り、VOC では SAM 3 が一番高い。** RF-DETR-Seg は COCO で学習しているので、
  COCO の画像・ラベルの付け方に合わせて伸びている可能性がある(確かめてはいない)。VOC ではサイズを上げても伸びが小さく(nano 0.557 → 2xlarge 0.577)、COCO(0.440 → 0.533)ほど差が出ない
- **小さい物体は SAM 3 が強い**(APs 0.329。RF-DETR-Seg は nano 0.144 〜 2xlarge 0.320)。大きい物体は RF-DETR-Seg が強い(APl 0.663〜0.688、SAM 3 0.616)。
  入力の大きさ(SAM 3 は 1008、RF-DETR-Seg は 312〜768)が効いている可能性があるが、入力の大きさだけを変えた比較はまだしていない
- **見つけた物体のマスクの形の正確さ(SQ)は、どのモデルも 0.814〜0.837 とほぼ同じ。** 見つけ方の良さ(RQ)の方が差が大きい(0.694〜0.754)
- **mask AP が 0.5 前後でも、見た目ではかなり良い。** IoU の閾値ごとの mask AP(coco_val_dev)は、RF-DETR-Seg 2xlarge が
  0.50: 0.789 / 0.75: 0.586 / 0.85: 0.359 / 0.90: 0.192 / 0.95: 0.045、SAM 3 が 0.50: 0.768 / 0.75: 0.542 / 0.85: 0.306 / 0.90: 0.148 / 0.95: 0.025 で、
  厳しい閾値(0.85 以上)がほとんど当たりにならないため平均が下がる。見つけた物体のマスクの IoU の平均(SQ)は 0.814〜0.837 で、
  見つけた物体は正解と 8 割強の重なりで合っている
- 速さは RF-DETR-Seg が SAM 3 の 11〜26 倍(199.1ms ÷ 18.6〜7.7ms)。nano(8.3ms)が small(7.7ms)より遅い理由は確かめていない

**動かし方**

- SAM 3: 公式の前処理のまま(1008×1008)、bf16。20 クラスの名前を文章として与え、画像の特徴を 1 回計算してから、20 クラスを 1 回の推論でまとめて処理した
  (公式の `Sam3Processor` は 1 クラスずつ処理するが、モデルは画像 × 文章の組を並べてまとめて処理できる。1 枚あたり 1,430ms → 199ms)。
  まとめて処理しても、1 クラスずつ処理したときと結果がほぼ同じことを、dev の先頭 200 枚で確かめた
  (mask AP 0.5560 / 0.5564、AP75 0.5904 / 0.5941、SQ 0.8255 / 0.8256。違いは bf16 の計算の違いで、スコアの低い予測の有無・順番が少し入れ替わる程度)。
  スコアが 0.01 以上の予測を残した(公式は 0.5 以上だけを返す)
- RF-DETR-Seg: ライブラリが勧める予測器(`model.inference()`。fp32 のまま、入力の大きさを固定して CUDA Graph で組み立てる)で、精度と時間の両方を測った。
  公式の速度の値(T4 + TensorRT fp16)とは条件が違う。1 枚あたり上位 100〜300 個(サイズによる)の予測をスコアの閾値なしで受け取り、20 クラスに当たるものだけを残した
- どちらも、遅延には画像の読み込み(JPEG のデコード)と、マスクを COCO 形式(RLE)に変える時間は入っていない

予測の見本の画像は `results/samples/`(COCO dev 12 枚・VOC 6 枚。正解と、SAM 3・RF-DETR-Seg の nano / large / 2xlarge の予測を、PQ と同じ閾値で描いたもの。
RF-DETR-Seg は比較対象なので、ファイルの大きさを抑えるため 3 サイズだけにした)。

### 合成データの画像生成にかかる時間(`measure_generation.py`)

合成データの主な生成モデル FLUX.2 [klein] 4B を、fp8 版の本体(4.07GB)で動かした。diffusers は倍率付きの fp8 を扱えないので、
読み込むときに「fp8 の値 × 倍率」で bf16 に戻している([lib_common/synthetic_data/flux2_klein.py](../../../lib_common/synthetic_data/flux2_klein.py))。step 数は蒸留版の既定の 4。
RTX 5090 で、ほかの処理と同時に動かさずに測った(warmup 2 枚の後の 8 枚)。

| 解像度 | 1 枚(中央値) | p90 | GPU メモリの最大 |
|---|---|---|---|
| 512×512 | 0.35 秒 | 0.36 秒 | 16.7GB |
| 768×768 | 0.59 秒 | 0.61 秒 | 17.5GB |
| 1024×1024 | 0.99 秒 | 1.01 秒 | 18.6GB |

- 読み込みは 22 秒。768×768 なら 1 時間に約 6,000 枚、1024×1024 なら約 3,600 枚(自動のラベル付け・確認の時間は別)
- 生成した画像がプロンプトどおりかを SAM 3 で確かめた(4 種類のプロンプト × 3 つの解像度の 12 枚): プロンプトに書いた物体は、
  1 つを除いて全部見つかり(スコア 0.77〜0.98)、写っていないはずのクラス(飛行機・馬・電車・船)は見つからなかった。
  ただし「羊と牛」のプロンプトでは、**どの解像度でも牛が 1 頭も描かれなかった**(羊は 9〜20 頭)。1 つのプロンプトに複数のクラスを入れると
  一部が描かれないことがあるので、合成データでは生成した画像に何が写っているかを確かめる手順が要る
- 見本の画像は `results/samples/generation/`({解像度}_prompt{番号}.jpg)

### 公式の値の再現(COCO val2017 の 5,000 枚・80 クラス)

評価のコードと動かし方が正しいかを確かめるため、公式と同じ条件(COCO val2017 全部・80 クラス)で評価した(`run_repro.sh`。セットは `coco_val2017_80cls`)。
精度だけを見るので、3 本を同時に流した(ここで記録した遅延は使わない)。

| RF-DETR-Seg | nano | small | medium | large | xlarge | 2xlarge |
|---|---|---|---|---|---|---|
| こちらの mask AP | 40.1 | 43.0 | 44.9 | 46.4 | 48.4 | 49.7 |
| 公式の mask AP | 40.3 | 43.1 | 45.3 | 47.1 | 48.8 | 49.9 |
| 差 | −0.2 | −0.1 | −0.4 | −0.7 | −0.4 | −0.2 |

- 公式の値をほぼ再現できた(差は 0.1〜0.7 ポイント)。どのサイズもこちらがわずかに低いが、原因(公式の評価の細かい条件との違いなど)は確かめていない

| SAM 3 | box AP | mask AP |
|---|---|---|
| こちら | 56.5 | 47.1 |
| 論文(表 1。COCO・クラス名を 1 つずつ与える) | 56.4 | (載っていない) |

- SAM 3 の box AP も論文の値を再現できた(差 +0.1)。論文の表は段組みが崩れていて、56.4 が COCO の box AP の列の値だという読み取りは確実ではない
- SAM 3 は、80 クラスを一度にまとめて推論すると VRAM(32GB)があふれて 1 枚 27 秒かかったので、20 クラスずつ 4 回に分けて推論した(`--class-chunk 20`)。
  予測が多くなりすぎないよう、スコアの下限は 0.05(20 クラスの評価では 0.01)

### 評価の仕組みの確認(`check_eval.py`)

答えのわかる予測を入れて、評価が正しく動くかを確かめた。

| 予測 | セット | mask AP | AP50 | AR100 | SQ | RQ | PQ | 正解ごとの最良の IoU の平均 | semantic mIoU | 前景の IoU |
|---|---|---|---|---|---|---|---|---|---|---|
| 正解のマスクをそのまま(スコア 1.0) | coco_val_dev | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 |
| | voc_val | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 |
| 正解を半分に減らす | coco_val_dev | 0.502 | 0.502 | 0.502 | 1.000 | 0.668 | 0.668 | 0.501 | 0.484 | 0.500 |
| | voc_val | 0.499 | 0.499 | 0.498 | 1.000 | 0.664 | 0.664 | 0.500 | 0.513 | 0.506 |
| クラスを 1 つずつずらす | coco_val_dev | 0.000 | 0.000 | 0.000 | - | - | - | - | - | - |
| | voc_val | 0.000 | 0.000 | 0.000 | - | - | - | - | - | - |
| 正解のマスクを 2 画素縮める | coco_val_dev | 0.414 | 0.672 | 0.548 | 0.809 | 0.791 | 0.649 | 0.633 | 0.915 | 0.927 |
| | voc_val | 0.508 | 0.788 | 0.618 | 0.824 | 0.854 | 0.714 | 0.728 | 0.882 | 0.908 |

- 正解そのままでは、box AP・Boundary AP・クラスごとの mask AP もすべて 1.000
- 半分に減らすと、RQ は計算どおり約 0.667(= 0.5 ÷ (0.5 + ½ × 0.5))、見つけた物体の形は正確なので SQ は 1.000 のまま
- 2 画素縮めると、AP50 が大きく下がるのは小さい物体のため。coco_val_dev の物体の 39%(3,920 個)が 32² 画素未満で、
  そのうち 70% は 2 画素縮めると IoU が 0.5 を下回る(中くらいの物体では 1.8%、大きい物体では 0%)。SQ・最良の IoU の平均は形のずれに応じて連続的に下がる
- 最初の実装では、正解そのままでも coco_val_dev の semantic mIoU が 0.984 になった。COCO の正解は別のクラスの物体のマスクが重なることがあり
  (物体の画素の 1.35%)、その画素のクラスが塗る順番で変わっていたため。重なる画素を計算に入れないように直した
